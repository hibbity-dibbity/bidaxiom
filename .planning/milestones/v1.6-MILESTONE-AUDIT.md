## Tech Debt Summary: 8 items across 4 phases

### Critical to fix (UX visible):

**Phase 44 — Missing getHeaderStats invalidation after inline approval actions** *(most actionable)*

After a user approves or rejects a CO (or approves/marks-paid a pay app) from the list view, the phase-level tab badge counts and the header contract value do NOT update until the React Query staleTime (5 min) expires or the user navigates away.

Affected files:
- `apps/web/components/change-order/change-order-list.tsx` — `approveMutation.onSuccess` (line 97), `rejectMutation.onSuccess` (line 106)
- `apps/web/components/payment-app/payment-app-list.tsx` — `approveMutation.onSuccess` (line 86), `markPaidMutation.onSuccess` (line 100)

Fix: Add `utils.project.getHeaderStats.invalidate({ projectId })` alongside the existing list invalidation in each of the 4 handlers. 4-line fix.

### Deferred (non-blocking):

**Phase 45 — `maxUnlockedStep` orphaned state in `useWorkflowState.ts`**
- The field is tracked and persisted but never read; Phase 45 removed the navigation gate. Clean up in v1.7.

**Phase 41 — Orange palette classes without dark: companions (3 occurrences)**
- `lien-waiver-tracker.tsx`, `change-order-list.tsx`, `change-order-detail.tsx` retain `bg-orange-500` / `bg-orange-500/10` / `text-orange-700` — documented intentional substitution for amber, no CSS token equivalent. Will break in dark mode.

**Phase 43 — CommitmentList ad-hoc empty state**
- Uses dashed-border JSX instead of shared `EmptyState` component. Not in LIST-03 scope but inconsistent.

**Phase 44 — `canCurrentUserApprove` cast via `as any`**
- Runtime field not in static TS type; documented decision. Will cause TypeScript issues if the type is ever audited.
