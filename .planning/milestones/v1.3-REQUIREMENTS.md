# Requirements: ConstructionSaaS v1.3

**Defined:** 2026-02-17
**Core Value:** A GC can issue an RFQ, subs can respond with bids, and both can manage the full project financial lifecycle (budget → change orders → pay applications) in one platform — with AI drafting assistance embedded throughout.

**Milestone Focus:** Polish, gap closure, and UX reliability — completing unfinished routing, fixing auth flows, consolidating account settings, and tightening the core user experience.

## v1.3 Requirements

### Session & Auth Flow

- [x] **SESS-01**: When session expires while the user is on a page, the app immediately redirects to the sign-in page (not discovered via a failed action) — *Satisfied Phase 25: useSessionWatcher hook + tRPC 401 interceptor*
- [x] **SESS-02**: After signing in, the user is redirected to the page they originally requested (return URL redirect completes correctly) — *Satisfied Phase 25: getSafeRedirectUrl + Server Component sign-in + MFA flow threading*

### Account Settings

- [x] **ACCT-01**: User can access a consolidated account settings page at /settings/account — *Satisfied Phase 26*
- [x] **ACCT-02**: Account settings page includes MFA configuration (enable, disable, QR code setup) — *Satisfied Phase 26*
- [x] **ACCT-03**: Account settings page includes password change functionality — *Satisfied Phase 26: auth.changePassword with refresh token revocation*
- [x] **ACCT-04**: User dropdown in top navigation links directly to /settings/account instead of separate Settings and MFA links — *Satisfied Phase 26*

### Navigation

- [x] **NAV-01**: Sidebar is static — always visible, no dynamic toggle; layout is consistent across all pages; dynamic sidebar code removed — *Satisfied Phase 26: collapsible="icon", project-context switching removed*

### Slug Routing

- [x] **SLUG-01**: Customer detail page is accessible via slug-based URL (e.g., /customers/abc-construction) — *Satisfied Phase 27: generateNameSlug (no UUID prefix)*
- [x] **SLUG-02**: Customer edit page uses slug-based URL — *Satisfied Phase 27: edit dialog on detail page + router.replace on rename*
- [x] **SLUG-03**: Subcontractor detail page uses slug-based URL (e.g., /subcontractors/smith-plumbing) — *Satisfied Phase 27*
- [x] **SLUG-04**: Subcontractor edit page uses slug-based URL — *Satisfied Phase 27: router.replace for post-rename navigation*

### Global Search

- [x] **SRCH-01**: Global search results include estimates alongside projects and customers — *Satisfied Phase 28: estimate query in search.ts + CommandGroup in command palette*
- [x] **SRCH-02**: Search result items display their type label (Project, Estimate, Customer) for clarity — *Satisfied Phase 28: separate labeled CommandGroup sections*

### Dashboard

- [x] **DASH-01**: Clicking a dashboard KPI widget navigates to the relevant page with pre-filtered results matching the widget's metric — *Satisfied Phase 28: 9 KPI widgets with router.push + query params*

### Job Number Edit

- [x] **JOBEDIT-01**: When a project's job number is manually changed on the edit project page, the company's auto-generation counter increments to prevent future duplicate job numbers — *Satisfied Phase 29: project.update advances nextSequenceNumber in DB transaction*

### UI/UX Polish

- [x] **UX-01**: List and table views display an informative empty state when no records exist (not a blank table) — *Satisfied Phase 29: change-order-list, commitment-list, payment-app-list, members upgraded*
- [x] **UX-02**: Data loading states are consistent — skeleton loaders or spinners appear during fetches instead of blank content areas — *Satisfied Phase 29: Skeleton rows in members/page.tsx*
- [x] **UX-03**: API errors surface consistently via toast notifications with actionable messages — *Satisfied Phase 29: QueryCache.onError in providers.tsx with id:"query-error" deduplication*
