## Design Notes (Non-Blocking)

These are informational findings from the integration check — not gaps requiring remediation before milestone completion.

### DN-01: `softDelete` does not re-validate lifecycle phase (Low Priority)

**File:** `apps/api/src/trpc/routers/project.ts`
**Observation:** The `softDelete` procedure does not independently call `BLOCKED_DELETION_PHASES` check — it trusts the UI to have called `checkDeletable` first. A direct tRPC API call bypassing the UI could soft-delete an "active" project.
**Assessment:** Acceptable design trade-off. Both procedures require `org:admin`. The UI always calls `checkDeletable` first. Defense-in-depth improvement, not a spec requirement.
**Action:** Deferred to v2.0 hardening.

### DN-02: PDF generation has no lifecycle phase gate at API layer (Informational)

**File:** `apps/api/src/trpc/routers/pdf.ts`
**Observation:** None of the four generate procedures call `isFeatureAvailableInPhase`. A user in "opportunity" phase can call `generateProposal` and receive a PDF.
**Assessment:** By design — generating a proposal PDF during the estimating/opportunity phase is a primary use case. No requirement in REQUIREMENTS.md blocks PDF generation by lifecycle phase. The absence of this gate is correct behavior.
**Action:** None required.
