## Cross-Phase Integration

**5 of 5 critical flows verified end-to-end. 0 broken flows.**

### Flow 1: Session Expiry → Sign-In → Return URL → Slug URL (25→27)
**Status: PASS**

Slug URL is captured verbatim by middleware and SessionWatcher → passed as `redirect_url` param → `getSafeRedirectUrl` validates → `router.push` navigates to slug route. Route exists at `customers/[customerSlug]` and `subcontractors/[subcontractorSlug]`. Complete chain verified.

*Minor observation (not a break):* `sign-in/page.tsx` passes `redirect_url` to `SignInForm` without calling `getSafeRedirectUrl` first. Validation fires at `router.push` time inside the form. No open-redirect exposure currently; defense-in-depth would validate at page level too.

### Flow 2: Slug Routing + Search Navigation (27→28)
**Status: PASS**

Command palette queries `trpc.search.global` → search router returns `url: /customers/${c.slug}` (not UUID — Phase 28 bug fix) and `url: /projects/${e.projectSlug}/estimates/${e.slug}`. `handleSelect` calls `router.push(url)`. All target routes exist. `isNotNull(estimates.slug)` guard prevents null-slug results.

### Flow 3: Account Settings + Session Revocation (25→26)
**Status: PASS**

`changePassword` mutation revokes all refresh tokens for the user. On other devices, the next token refresh fails → SessionWatcher detects 401 → redirects to sign-in with return URL. Current device retains session until JWT expiry (intended — user stays signed in on current device after password change).

*Observation:* MFA `hasMfa` state in the settings UI is login-time state. After `disableMfa`, UI still shows "Enabled" until re-login or page refresh. This is documented per Phase 26 decisions and is a known UX gap, not a break.

### Flow 4: Project Create/Edit → Job Number Counter → Settings Display (21→29)
**Status: PASS**

`project.create` and `project.update` both advance `nextSequenceNumber` in `companyProfiles` inside `db.transaction`. Both component `onSuccess` handlers call `utils.company.getCurrent.invalidate()` and `utils.company.getMaxUsedJobSequence.invalidate()`. Settings page shows accurate counter after any project save.

*Documentation note:* 29-04 SUMMARY incorrectly states cache invalidation was added to `providers.tsx`. Actual location is `project-form.tsx` (create) and `edit/page.tsx` (update). Code is correct; SUMMARY has a minor documentation error.

### Flow 5: Global Error Handler + Mutation Errors (Phase 29)
**Status: PASS**

`QueryCache.onError` fires for query failures only. No `MutationCache.onError` present (intentional — avoids double-toasting). Per-mutation `onError` callbacks handle mutation failures. `id: "query-error"` deduplicates toast on React Query retries. Verified by Phase 29 UAT.
