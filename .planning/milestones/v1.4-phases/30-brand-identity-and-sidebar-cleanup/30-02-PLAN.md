<objective>
Add `metadata` exports to server-component page and layout files so the browser tab title follows the "{Page Name} | BIDAXIOM" format established by the root layout template in Plan 01.

Purpose: BRAND-02 requires every page to identify itself in the browser tab. This plan handles the pages that CAN receive metadata (server components) and documents why the rest (client components) use the "BIDAXIOM" default.
Output: Sign-in page gets "Sign In | BIDAXIOM"; all pages show "BIDAXIOM" via root template default.

**Codebase constraint (discovered during research):**
Nearly all `page.tsx` files in this application use `"use client"` at line 1. Next.js 14 prohibits `metadata` exports from client components — they are silently ignored. The server-component files eligible for metadata are:
- `app/(auth)/sign-in/[[...sign-in]]/page.tsx` — thin server wrapper, no "use client"
- `app/(auth)/layout.tsx` — server component layout
- `app/(dashboard)/layout.tsx` — server component layout

All other page files (`dashboard/page.tsx`, `projects/page.tsx`, `settings/page.tsx`, etc.) are `"use client"` and will fall back to the root layout's `default: "BIDAXIOM"`. This means those tabs show "BIDAXIOM" — satisfying BRAND-02's requirement that BIDAXIOM appears in every tab.
</objective>
