**bid-comparison-table.tsx:**

The `adjustmentAmount` field is OPTIONAL — the mutation receives `undefined` when no adjustment is provided. The existing code stores it as `""` (string) and passes `adjustmentAmount ? parseFloat(adjustmentAmount) : undefined` to the mutation. We must preserve this optional semantics.

Strategy: Keep `adjustmentAmount` as a number | undefined in state, defaulting to `undefined`. CurrencyInput needs a number, so pass `adjustmentAmount ?? 0`. On change: if `n === 0`, set state to `undefined`; else set state to `n`.

1. Add import: `import { CurrencyInput } from "@/components/ui/currency-input";`
2. Also add: `import { parseCurrencyInput } from "@/lib/utils/format";` (needed to check if field is empty)

3. Change state: `const [adjustmentAmount, setAdjustmentAmount] = useState<number | undefined>(undefined);`

4. Reset in addLevelingNoteMutation onSuccess: `setAdjustmentAmount(undefined);`

5. In `submitLevelingNote`, change:
```tsx
adjustmentAmount: adjustmentAmount ? parseFloat(adjustmentAmount) : undefined,
```
to:
```tsx
adjustmentAmount: adjustmentAmount,
```
(already a number | undefined)

6. Replace the adjustment Input (around line 437-444):
```tsx
<Input
  id="adjustment"
  type="number"
  step="0.01"
  value={adjustmentAmount}
  onChange={(e) => setAdjustmentAmount(e.target.value)}
  placeholder="0.00"
/>
```
Replace with:
```tsx
<CurrencyInput
  id="adjustment"
  value={adjustmentAmount ?? 0}
  onChange={(n) => setAdjustmentAmount(n === 0 ? undefined : n)}
  placeholder="0.00"
/>
```

This preserves the optional semantics: if the user clears the field (CurrencyInput calls onChange(0)), state becomes `undefined`, and the mutation receives no adjustmentAmount.
