<objective>
Fix SESS-02: After signing in, users land back where they intended — not always the dashboard.

Purpose: The sign-in page currently calls `useSearchParams()` in a `"use client"` component without a Suspense boundary. In Next.js 14 production builds this causes a CSR bailout that makes `redirect_url` always empty. Additionally, the MFA sub-flow discards the return URL when routing to `/mfa-setup`, breaking the flow for MFA-enabled users.

Output:
- `safe-redirect.ts` — validated redirect URL helper
- `sign-in-form.tsx` — extracted client component (form logic)
- `page.tsx` — thin Server Component reading `searchParams` prop (eliminates `useSearchParams`)
- `mfa-setup/page.tsx` — updated to read and forward `redirect_url` through the MFA completion flow
</objective>
