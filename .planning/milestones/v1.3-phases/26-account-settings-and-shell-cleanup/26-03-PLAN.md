      currentPassword: z.string().min(1, "Current password is required"),

    **Section 3 — Two-Factor Authentication:**
    Card with title "Two-Factor Authentication", description "Add an extra layer of security to your account."

    Read MFA status from `user?.mfaEnabled` (boolean from auth context).

    **If MFA is enabled (`user?.mfaEnabled === true`):**
    Show a green status badge: `<span className="inline-flex items-center gap-1.5 text-sm text-green-600"><Shield className="h-4 w-4" /> Enabled</span>`

    Below it, show a "Disable MFA" section:
    - Brief description: "To disable MFA, confirm your password."
    - An inline password input (`disableMfaPassword` state, type="password", placeholder="Enter your password")
    - A "Disable MFA" Button (variant="destructive") that calls `onDisableMfa`
    - While disabling: show `<Loader2>` in button, disable the input

    `onDisableMfa` handler:
    1. If `disableMfaPassword` is empty, `toast.error("Please enter your password")` and return
    2. Set `isDisablingMfa = true`
    3. Fetch `GET /api/auth/token` to get `accessToken`
    4. POST to `${API_URL}/trpc/auth.disableMfa` with Bearer token and body `JSON.stringify({ json: { currentPassword: disableMfaPassword } })`
    5. On success: `toast.success("MFA has been disabled")`, clear `disableMfaPassword`. The page will reflect the new state on next load/refresh (the auth context reflects login-time mfaEnabled; user will see the change after refreshing).
    6. On error: `toast.error(result.error?.json?.message || "Failed to disable MFA")`
    7. Always: `setIsDisablingMfa(false)`

    **If MFA is not enabled (`!user?.mfaEnabled`):**
    Show a grey status badge: `<span className="inline-flex items-center gap-1.5 text-sm text-muted-foreground"><Shield className="h-4 w-4" /> Not enabled</span>`

    Below it, show:
    - Description: "Protect your account with a time-based one-time password (TOTP) authenticator app."
    - A "Set Up MFA" Button (variant="outline", asChild) wrapping a `<Link href="/mfa-setup?redirect_url=/settings/account">`. This reuses the existing /mfa-setup flow and redirects back to account settings after completion.
