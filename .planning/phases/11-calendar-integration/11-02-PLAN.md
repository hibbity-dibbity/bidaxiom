**Create `apps/api/src/integrations/calendar/google/oauth.ts`:**

Follow the QBO oauth.ts pattern but use Google's `googleapis` SDK:

1. `createGoogleOAuth2Client()` -- internal helper:
   - Uses `google.auth.OAuth2` with GOOGLE_CALENDAR_CLIENT_ID, GOOGLE_CALENDAR_CLIENT_SECRET
   - Redirect URI: `${API_URL}/api/integrations/calendar/google/callback`
   - Throws if env vars missing

2. `getGoogleCalendarAuthUrl(tenantId: string, userId: string)`: string
   - Calls `oauth2Client.generateAuthUrl()`
   - `access_type: 'offline'` (CRITICAL for refresh token)
   - `prompt: 'consent'` (force consent to guarantee refresh token)
   - Scopes: `['https://www.googleapis.com/auth/calendar.events', 'https://www.googleapis.com/auth/calendar.readonly']`
   - State: JSON.stringify({ tenantId, userId }) -- both needed for callback
   - Returns authorization URL

3. `handleGoogleCalendarCallback(code: string, state: string)`: Promise<GoogleCalendarTokens>
   - Parses state to get tenantId, userId
   - Exchanges code for tokens: `oauth2Client.getToken(code)`
   - Returns: { accessToken, refreshToken, tokenExpiresAt, tenantId, userId, providerEmail? }
   - Note: Google does NOT rotate refresh tokens (unlike QBO)

4. `refreshGoogleCalendarToken(refreshToken: string)`: Promise<{ accessToken, tokenExpiresAt }>
   - Decrypts refresh token
   - Sets credentials on oauth2Client
   - Calls `oauth2Client.refreshAccessToken()`
   - Returns new access token and expiry (refresh token stays the same for Google)

Export interface `GoogleCalendarTokens` with all returned fields.

**Create `apps/api/src/integrations/calendar/google/client.ts`:**

1. `createGoogleCalendarClient(accessToken: string)`:
   - Creates `google.auth.OAuth2()` client, sets `access_token` credential
   - Returns `google.calendar({ version: 'v3', auth: oauth2Client })`
   - This client object is used for events.list, events.insert, events.update, events.delete, events.watch

**Create `apps/api/src/integrations/calendar/microsoft/oauth.ts`:**

Use `@azure/msal-node` ConfidentialClientApplication:

1. `createMsalClient()` -- internal helper:
   - Uses MICROSOFT_CALENDAR_CLIENT_ID, MICROSOFT_CALENDAR_CLIENT_SECRET
   - Authority: `https://login.microsoftonline.com/common` (multi-tenant)
   - Throws if env vars missing

2. `getMicrosoftCalendarAuthUrl(tenantId: string, userId: string)`: Promise<string>
   - Calls `cca.getAuthCodeUrl()`
   - Scopes: `['Calendars.ReadWrite', 'offline_access', 'User.Read']`
   - Redirect URI: `${API_URL}/api/integrations/calendar/microsoft/callback`
   - State: JSON.stringify({ tenantId, userId })
   - Returns authorization URL

3. `handleMicrosoftCalendarCallback(code: string, state: string)`: Promise<MicrosoftCalendarTokens>
   - Parses state to get tenantId, userId
   - Calls `cca.acquireTokenByCode({ code, scopes, redirectUri })`
   - Returns: { accessToken, refreshToken (from response.account), tokenExpiresAt, tenantId, userId, providerEmail }
   - Note: MSAL caches tokens internally; we extract and store ourselves for multi-tenant support

4. `refreshMicrosoftCalendarToken(encryptedRefreshToken: string)`: Promise<{ accessToken, tokenExpiresAt, newRefreshToken? }>
   - Decrypts refresh token
   - Calls `cca.acquireTokenByRefreshToken({ refreshToken, scopes })`
   - CRITICAL: Microsoft MAY rotate refresh token -- if new one returned, caller must store it
   - Returns new access token, expiry, and optionally new refresh token

Export interface `MicrosoftCalendarTokens`.
