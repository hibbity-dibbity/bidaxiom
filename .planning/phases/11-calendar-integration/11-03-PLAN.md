**Create `apps/api/src/integrations/calendar/shared/mappers.ts`:**

Maps between platform milestones and calendar event formats.

1. `projectToCalendarEvents(project, phases)` -- takes a project record (from projects table) and its phases (from projectPhases table), returns an array of calendar event objects ready for creation:
   - **Project start event:** If project.startDate exists, create event: title = `[${project.name}] Project Start`, date = project.startDate, allDay = true, sourceEntityType = "project", sourceEntityId = project.id
   - **Project end event:** If project.endDate exists, create event: title = `[${project.name}] Project End / Deadline`, date = project.endDate, allDay = true, sourceEntityType = "project", sourceEntityId = project.id
   - **Phase events:** For each phase with a startDate or endDate:
     - If startDate: title = `[${project.name}] ${phase.name} Start`, allDay = true, sourceEntityType = "project_phase", sourceEntityId = phase.id
     - If endDate: title = `[${project.name}] ${phase.name} End`, allDay = true, sourceEntityType = "project_phase", sourceEntityId = phase.id
   - Return type: `Array<{ title, description, startDate, endDate?, allDay, sourceEntityType, sourceEntityId }>`

2. `mapGoogleEventToInternal(googleEvent)` -- converts Google Calendar API event to internal format:
   - Maps: id -> externalEventId, summary -> title, description -> description
   - Dates: event.start.dateTime (timed) or event.start.date (all-day) -> startDate
   - All-day detection: event.start.date exists (no dateTime)
   - Timezone: event.start.timeZone
   - Etag: event.etag
   - Cancelled: event.status === 'cancelled' means deleted

3. `mapMicrosoftEventToInternal(msEvent)` -- converts Microsoft Graph event to internal format:
   - Maps: id -> externalEventId, subject -> title, body.content -> description
   - Dates: start.dateTime -> startDate, end.dateTime -> endDate
   - All-day: isAllDay property
   - Timezone: start.timeZone
   - Deleted: '@removed' property on event means deleted

4. `internalToGoogleEvent(internalEvent)` -- converts internal event to Google Calendar API format:
   - title -> summary, description -> description
   - For all-day: use `date` field (YYYY-MM-DD format, no time)
   - For timed: use `dateTime` field (ISO 8601)

5. `internalToMicrosoftEvent(internalEvent)` -- converts internal event to Microsoft Graph format:
   - title -> subject, description -> body { contentType: 'text', content: description }
   - start: { dateTime, timeZone }, end: { dateTime, timeZone }
   - isAllDay for all-day events

**Create `apps/api/src/integrations/calendar/google/sync.ts`:**

1. `syncGoogleCalendar(connection, db, schema)` -- incremental sync using syncToken:
   - If connection.syncToken exists: use it for incremental sync (params.syncToken)
   - If no syncToken: full sync with timeMin = 30 days ago (initial sync)
   - Paginate with nextPageToken until nextSyncToken received
   - For each event in response:
     - If status === 'cancelled': delete from calendarEvents table where externalEventId matches
     - Otherwise: upsert into calendarEvents (insert or update on conflict by externalEventId + connectionId)
   - Store new syncToken on connection record
   - Update calendarSyncState with syncedEventCount, lastIncrementalSyncAt
   - Handle 410 Gone error (syncToken expired): clear syncToken, retry with full sync
   - Returns { synced: number, deleted: number, newSyncToken }

2. `pushEventToGoogle(connection, eventData)` -- create event on Google Calendar:
   - Uses createGoogleCalendarClient(connection.accessToken)
   - Calls calendar.events.insert({ calendarId: connection.calendarId, requestBody: internalToGoogleEvent(eventData) })
   - Returns the created Google event (including event ID and etag)

3. `updateGoogleEvent(connection, externalEventId, eventData)` -- update existing event:
   - Uses If-Match header with stored etag for conflict detection
   - On 412 Precondition Failed: re-fetch event, apply last-write-wins based on updatedAt timestamp
   - Returns updated event

4. `deleteGoogleEvent(connection, externalEventId)` -- delete event from Google Calendar:
   - Calls calendar.events.delete({ calendarId, eventId })
   - Handles 404 (already deleted) gracefully

**Create `apps/api/src/integrations/calendar/google/webhooks.ts`:**

1. `setupGoogleWebhook(connection, db, schema)` -- create push notification channel:
   - Channel ID: `cal-${connection.id}-${Date.now()}`
   - Address: `${API_URL}/api/webhooks/calendar/google`
   - Expiration: 7 days from now
   - Token: connection.id (for validation)
   - Stores channelId, resourceId, webhookExpiresAt on connection record
   - Queues renewal job: calendarSyncQueue.add('renew-webhook', { ... }, { delay: 6 days })

2. `handleGoogleWebhookNotification(headers)` -- process incoming webhook:
   - Validates x-goog-channel-id, x-goog-channel-token headers
   - Returns 200 for 'sync' resourceState (setup confirmation)
   - For 'exists' (change occurred): returns { connectionId, shouldSync: true }
   - For unknown/invalid: returns { shouldSync: false }

3. `renewGoogleChannel(connection, db, schema)` -- stop old channel, create new one:
   - Stop existing: calendar.channels.stop({ id: channelId, resourceId })
   - Create new channel via setupGoogleWebhook

4. `stopGoogleChannel(connection)` -- stop watching:
   - Calls calendar.channels.stop()
   - Handles errors gracefully (channel may already be expired)

**Create `apps/api/src/integrations/calendar/microsoft/sync.ts`:**

1. `syncMicrosoftCalendar(connection, db, schema)` -- delta sync:
   - If connection.syncToken (deltaLink) exists: use it as URL
   - If no deltaLink: use `/me/calendarView/delta?startDateTime=30daysAgo&endDateTime=1yearFromNow`
   - Paginate with @odata.nextLink until @odata.deltaLink received
   - For each event: check for '@removed' property (deletion), otherwise upsert
   - Store new deltaLink as syncToken on connection
   - Handle 410 Gone (deltaLink expired): clear, retry with full sync
   - Returns { synced, deleted, newDeltaToken }

2. `pushEventToMicrosoft(connection, eventData)` -- create event:
   - Uses createMicrosoftGraphClient(connection.accessToken)
   - POST /me/calendar/events with internalToMicrosoftEvent(eventData)
   - Returns created event with ID

3. `updateMicrosoftEvent(connection, externalEventId, eventData)` -- update event:
   - PATCH /me/calendar/events/{id}
   - Returns updated event

4. `deleteMicrosoftEvent(connection, externalEventId)` -- delete event:
   - DELETE /me/calendar/events/{id}
   - Handle 404 gracefully

**Create `apps/api/src/integrations/calendar/microsoft/webhooks.ts`:**

1. `setupMicrosoftWebhook(connection, db, schema)`:
   - POST /subscriptions
   - changeType: 'created,updated,deleted'
   - notificationUrl: `${API_URL}/api/webhooks/calendar/microsoft`
   - resource: `/me/calendars/${connection.calendarId}/events`
   - expirationDateTime: 3 days from now (Microsoft calendar max is ~4230 minutes)
   - clientState: connection.id
   - Stores subscriptionId, webhookExpiresAt
   - Queues renewal job with delay: 2 days

2. `handleMicrosoftWebhookNotification(body, query)`:
   - Handles validation request: if query.validationToken exists, return it as plain text
   - For notifications: extract subscriptionId, clientState, return { connectionId, shouldSync: true }

3. `renewMicrosoftSubscription(connection, db, schema)`:
   - PATCH /subscriptions/{subscriptionId} with new expirationDateTime
   - Update webhookExpiresAt on connection record
   - Queue next renewal

All sync functions accept `db` and `schema` parameters from the worker (not building their own tenant context). This follows the Phase 8 QBO mapper pattern -- keeps sync functions pure and testable.

**Create `apps/api/src/integrations/calendar/shared/workers.ts`:**

Follow the QBO sync worker pattern from `apps/api/src/integrations/quickbooks/sync/workers.ts`.

1. `startCalendarSyncWorker()` -- creates and returns BullMQ Worker:
   - Queue name: 'calendar-sync'
   - Connection: redisConnection (from QBO queue)
   - Concurrency: 3 (conservative -- calendar APIs have strict rate limits)
   - Rate limiter: max 60 per minute (well under Google's 1M/day and Microsoft's per-mailbox limits)

2. **Job processor function** handles all CalendarSyncJobData operations:

   **Common preamble for all jobs:**
   - Load calendar connection from DB (calendarConnections table) using connectionId
   - If connection not found or status !== 'active': log warning, return
   - Check if access token is expired (tokenExpiresAt <= now):
     - If expired: call refreshGoogleCalendarToken or refreshMicrosoftCalendarToken
     - Store new access token (and new refresh token for Microsoft if rotated)
     - Encrypt new refresh token if changed
   - Build tenant DB context: get tenantId from job data, get schema name from public tenants table, create tenant schema + drizzle db

   **Operation routing:**

   a. `full-sync`:
      - Update calendarSyncState to syncStatus: 'syncing'
      - Clear connection.syncToken (force full sync)
      - Call syncGoogleCalendar or syncMicrosoftCalendar based on provider
      - Update calendarSyncState: syncStatus: 'synced', lastFullSyncAt: now, syncedEventCount
      - On error: update syncStatus: 'error', errorCount++, lastError

   b. `incremental-sync`:
      - Update calendarSyncState to syncStatus: 'syncing'
      - Call syncGoogleCalendar or syncMicrosoftCalendar (will use syncToken if available)
      - Update calendarSyncState: syncStatus: 'synced', lastIncrementalSyncAt: now
      - On error: update syncStatus: 'error', errorCount++

   c. `push-event`:
      - Load project (and phases if needed) from tenant DB
      - Generate calendar events via projectToCalendarEvents(project, phases)
      - For each event: check if already exists in calendarEvents table (by sourceEntityType + sourceEntityId + connectionId)
        - If exists: call updateGoogleEvent/updateMicrosoftEvent
        - If not: call pushEventToGoogle/pushEventToMicrosoft, insert into calendarEvents table with externalEventId
      - Update lastSyncAt on connection

   d. `delete-event`:
      - Load calendar event from calendarEvents table by eventId
      - Call deleteGoogleEvent/deleteMicrosoftEvent
      - Delete row from calendarEvents table

   e. `renew-webhook`:
      - Call renewGoogleChannel or renewMicrosoftSubscription
      - Log success/failure

3. **Error handling:**
   - On job failure (all retries exhausted): log error, update calendarSyncState with error info
   - Token refresh errors: mark connection status as 'expired', log for user visibility
   - Network errors: BullMQ exponential backoff handles retry

4. **Worker event listeners:**
   - 'completed': log job completion
   - 'failed': log job failure with error message
   - 'error': log worker-level errors

Export: `startCalendarSyncWorker()` returning the Worker instance.
