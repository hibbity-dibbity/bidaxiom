Add `canCurrentUserApprove` boolean to both the CO list and pay app list API endpoints. This is computed via a single bulk inArray query against the approval steps tables — not a per-row query — so the list endpoints remain N+1-free.

Purpose: The inline Approve/Reject/Mark Paid buttons in Plans 02 and 03 need this field to decide whether to render action buttons per row. Without it, the UI cannot know if the current user is the designated approver for a given item.
Output: Two modified router files; both list endpoints return canCurrentUserApprove on each record.
</objective>

In the `list` procedure (line ~226), after the main `changeOrders` query and `lineItemCounts` query, add a third bulk query for pending approval steps:

1. Guard against empty list: if `changeOrders.length === 0`, skip the steps query entirely and return each CO with `canCurrentUserApprove: false`.

2. Otherwise, query `approvalWorkflowSteps` in bulk:
```ts
const pendingSteps = changeOrders.length > 0
  ? await db
      .select()
      .from(schema.approvalWorkflowSteps)
      .where(
        and(
          inArray(schema.approvalWorkflowSteps.changeOrderId, changeOrders.map(co => co.id)),
          eq(schema.approvalWorkflowSteps.status, "pending")
        )
      )
  : [];
```

3. Compute `canCurrentUserApprove` per CO by finding the first pending step for that CO and applying the same role logic used in the approve mutation:
```ts
const normalizedRole = ctx.orgRole?.startsWith("org:") ? ctx.orgRole : `org:${ctx.orgRole}`;
const pendingStepMap = new Map<string, typeof pendingSteps[number]>();
for (const step of pendingSteps) {
  if (!pendingStepMap.has(step.changeOrderId)) {
    pendingStepMap.set(step.changeOrderId, step);
  }
}
```

4. In the return `.map()` call, add `canCurrentUserApprove` to each object:
```ts
const pendingStep = pendingStepMap.get(co.id);
const canCurrentUserApprove = pendingStep
  ? (pendingStep.approverUserId === ctx.userId) ||
    (!!pendingStep.approverRole && pendingStep.approverRole === normalizedRole) ||
    (!pendingStep.approverUserId && !pendingStep.approverRole)
  : false;
return { ...co, lineItemCount: countMap.get(co.id) ?? 0, canCurrentUserApprove };
```

The `normalizedRole` computation must be placed BEFORE the map so it is not recalculated per row.
