  <action>
Create **commitment.ts** tRPC router following the same patterns as budget.ts and project.ts:

Import loadProjectAbilities pattern (copy from budget.ts or project.ts). Import shared schemas: `createCommitmentSchema`, `updateCommitmentSchema`, `commitmentStatusEnum`, `AuditAction` from `@construction/shared`.

Define valid status transitions as a const map:
```typescript
const VALID_STATUS_TRANSITIONS: Record<string, string[]> = {
  draft: ["pending", "closed"],
  pending: ["approved", "draft", "closed"],
  approved: ["executed", "pending", "closed"],
  executed: ["closed"],
  closed: [], // Terminal state
};
```

Procedures:

1. **commitment.create** (mutation):
   - Input: `createCommitmentSchema`
   - Load project abilities, check `can("create", "Commitment")`
   - Calculate totalAmount from sum of lineItems amounts
   - For each line item with a budgetLineItemId:
     - Verify the budget line item exists and belongs to the same project
     - Query existing committed amount for that budget line item (SUM of commitment_line_items.amount for all executed/approved commitments)
     - Calculate what the new total committed would be
     - If newTotalCommitted > budgetedAmount: don't block, but include warning in response
   - Use transaction: insert commitment, then insert all commitment_line_items
   - Set commitment totalAmount = sum of line items (server-calculated, not client input)
   - Create audit log with AuditAction.CREATE
   - Return `{ commitment, lineItems, warnings }` where warnings is array of `{ budgetLineItemId, budgeted, currentCommitted, newCommitted, exceedsBy }` for any over-budget items

2. **commitment.list** (query):
   - Input: `z.object({ projectId: z.string().uuid(), status: commitmentStatusEnum.optional(), type: commitmentTypeEnum.optional() })`
   - Load project abilities, check `can("read", "Commitment")`
   - Select commitments WHERE projectId, with optional status and type filters
   - Order by createdAt DESC
   - For each commitment, also query its line items count and total amount
   - Return array of commitments with metadata

3. **commitment.getById** (query):
   - Input: `z.object({ id: z.string().uuid() })`
   - Load project abilities (from commitment's projectId), check `can("read", "Commitment")`
   - Fetch commitment with its line items (including linked budget line item descriptions)
   - Return commitment with full line item details

4. **commitment.update** (mutation):
   - Input: `updateCommitmentSchema`
   - Fetch commitment, check exists
   - If status change requested, validate transition:
     - Check current status allows transition to new status (using VALID_STATUS_TRANSITIONS map)
     - If invalid, throw BAD_REQUEST: "Cannot transition from {current} to {new}"
     - If transitioning to "executed": set executedAt = new Date()
     - If transitioning to "approved": set approvedBy = ctx.userId, approvedAt = new Date()
   - Load project abilities, check `can("update", "Commitment")`
   - Update fields, set updatedAt = new Date()
   - Create audit log with before/after values
   - Return updated commitment

5. **commitment.delete** (mutation):
   - Input: `z.object({ id: z.string().uuid() })`
   - Fetch commitment, check exists
   - Only allow deletion if status is "draft" — throw FORBIDDEN for any other status: "Only draft commitments can be deleted. Close the commitment instead."
   - Load project abilities, check `can("delete", "Commitment")`
   - Delete commitment (CASCADE deletes line items)
   - Create audit log
   - Return `{ success: true }`

6. **commitment.getLineItems** (query):
   - Input: `z.object({ commitmentId: z.string().uuid() })`
   - Fetch commitment to get projectId
   - Load project abilities, check `can("read", "Commitment")`
   - Query commitment_line_items WHERE commitmentId
   - LEFT JOIN budget_line_items to include budget description and budgeted amount
   - Return array of line items with budget context

All procedures use `protectedProcedure` and follow the established patterns:
- Verify tenant exists (already handled by protectedProcedure)
- Load project abilities via team membership query
- CASL permission check
- Database operation
- Audit log on mutations
- Return typed result
