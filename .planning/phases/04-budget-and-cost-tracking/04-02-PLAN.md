  <action>
Create the `apps/api/src/calculations/` directory with two modules:

**variance.ts** — Budget variance calculation and alert generation:

Export `checkBudgetVariances(projectId, tenantDb, schema, thresholds?)`:
- Takes projectId (string), tenant db instance, tenant schema, optional thresholds `{ warning: number, critical: number }` defaulting to `{ warning: 0.10, critical: 0.20 }`
- Query budget_line_items LEFT JOIN commitment_line_items (via budgetLineItemId)
- LEFT JOIN commitments to filter only executed commitments (status = 'executed')
- GROUP BY budget line item to get total committed per line item
- Calculate variance: budgeted - committed
- Calculate variancePercent: |variance| / budgeted (handle budgeted = 0)
- Determine severity: if committed > budgeted AND variancePercent >= critical → "critical", elif >= warning → "warning", else "ok"
- Return array of `VarianceAlert` objects (import type from @construction/shared)
- Use `sql` template literals for aggregation, import from `drizzle-orm`
- Handle NUMERIC conversion: cast query results to Number() since PostgreSQL NUMERIC returns strings

**forecast.ts** — Earned Value Management forecast calculation:

Export `calculateForecast(projectId, tenantDb, schema)`:
- Takes projectId (string), tenant db instance, tenant schema
- Query 1: SUM(budgeted_amount) from budget_line_items WHERE projectId → budgetAtCompletion (BAC)
- Query 2: SUM(total_amount) from commitments WHERE projectId AND status = 'executed' → committedCost
- actualCost: For Phase 4, actual costs come from commitments (payment applications are Phase 6). Use committedCost as proxy.
- earnedValue: Calculate as percentage of committed items that are executed. Simplified: `(committedCost / budgetAtCompletion) * budgetAtCompletion` if there are commitments, else 0. This is a simplified EV — Phase 6 will refine with payment app data.
- costPerformanceIndex (CPI): earnedValue / actualCost. Guard: if actualCost = 0, CPI = 1.0
- estimateAtCompletion (EAC): budgetAtCompletion / CPI
- estimateToComplete (ETC): EAC - actualCost
- varianceAtCompletion (VAC): budgetAtCompletion - EAC
- Return `ForecastMetrics` object (import type from @construction/shared)
- Handle edge cases: empty project (no budget) returns all zeros with CPI = 1.0
- All number conversions handle PostgreSQL NUMERIC strings via Number()

Both modules should use typed imports from the tenant schema and drizzle-orm operators (eq, and, sql, sum). Follow the same pattern as existing routers for DB access.

  <action>
Create **budget.ts** tRPC router following the same patterns as `project.ts` and `document.ts`:

Import `loadProjectAbilities` pattern — copy the helper function from project.ts (queries team memberships, builds CASL abilities). Or better: extract and import if it's already exported. If not, duplicate the pattern locally.

Import shared schemas: `createBudgetLineItemSchema`, `updateBudgetLineItemSchema`, `AuditAction`, `CSI_DIVISIONS` from `@construction/shared`.

Import calculation helpers: `checkBudgetVariances` from `../../calculations/variance.js`, `calculateForecast` from `../../calculations/forecast.js`.

Procedures:

1. **budget.createLineItem** (mutation):
   - Input: `createBudgetLineItemSchema`
   - Load project abilities, check `can("update", "Budget")`
   - Validate cost code: if costCodeId < 50, check it exists in CSI_DIVISIONS; if >= 50, check it's a valid custom code (for now, accept any >= 50 since company cost code config will be validated in future). Basic validation: costCodeId must be non-negative.
   - Insert into budget_line_items with `budgetedAmount: input.budgetedAmount.toFixed(2)`
   - Create audit log with AuditAction.CREATE
   - Return created line item

2. **budget.listLineItems** (query):
   - Input: `z.object({ projectId: z.string().uuid() })`
   - Load project abilities, check `can("read", "Budget")`
   - Select all budget_line_items WHERE projectId, ORDER BY costCodeId ASC, createdAt ASC
   - Return array of line items

3. **budget.updateLineItem** (mutation):
   - Input: `updateBudgetLineItemSchema`
   - Fetch line item, check it exists
   - **CRITICAL: Check isLocked — if true, throw FORBIDDEN: "Budget line item is locked. Use change order to modify."**
   - Load project abilities for the line item's projectId, check `can("update", "Budget")`
   - Update fields (only provided optional fields), set updatedAt = new Date()
   - Create audit log with before/after values
   - Return updated line item

4. **budget.deleteLineItem** (mutation):
   - Input: `z.object({ id: z.string().uuid() })`
   - Fetch line item, check it exists
   - **Check isLocked — if true, throw FORBIDDEN**
   - Check no commitment_line_items reference this budget line item (query count). If any exist, throw BAD_REQUEST: "Cannot delete budget line item with associated commitments. Remove commitments first."
   - Load project abilities, check `can("delete", "Budget")`
   - Delete from budget_line_items
   - Create audit log
   - Return `{ success: true }`

5. **budget.getProjectSummary** (query):
   - Input: `z.object({ projectId: z.string().uuid() })`
   - Load project abilities, check `can("read", "Budget")`
   - Query: SUM(budgetedAmount) from budget_line_items WHERE projectId → totalBudgeted
   - Query: COUNT budget_line_items WHERE projectId → lineItemCount
   - Query: SUM(totalAmount) from commitments WHERE projectId AND status IN ('approved', 'executed') → totalCommitted
   - Query: COUNT commitments WHERE projectId → commitmentCount
   - totalActual: 0 (deferred to Phase 6 payment applications)
   - totalVariance: totalBudgeted - totalCommitted
   - Return `BudgetSummary` object

6. **budget.getVarianceAlerts** (query):
   - Input: `z.object({ projectId: z.string().uuid() })`
   - Load project abilities, check `can("read", "Budget")`
   - Call `checkBudgetVariances(projectId, ctx.tenant.db, ctx.tenant.schema)`
   - Filter to only warning and critical severity
   - Return filtered alerts array

7. **budget.getForecast** (query):
   - Input: `z.object({ projectId: z.string().uuid() })`
   - Load project abilities, check `can("read", "Budget")`
   - Call `calculateForecast(projectId, ctx.tenant.db, ctx.tenant.schema)`
   - Return ForecastMetrics object

8. **budget.lockLineItem** (mutation):
   - Input: `z.object({ id: z.string().uuid() })`
   - Fetch line item, check exists
   - If already locked, return it as-is (idempotent)
   - Load project abilities, check `can("update", "Budget")`
   - Update: isLocked = true, lockedAt = new Date(), lockedBy = ctx.userId
   - Create audit log
   - Return locked line item
   - Note: This will be called from Phase 6 when payment applications are created. For now it's available for manual use.

In **router.ts**, import and register budgetRouter:
