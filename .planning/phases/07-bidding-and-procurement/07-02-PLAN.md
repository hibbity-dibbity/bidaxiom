<task type="auto">
  <name>Task 1: Create RFQ tRPC router with lifecycle management</name>
  <files>
    apps/api/src/trpc/routers/rfq.ts
  </files>
  <action>
Create `apps/api/src/trpc/routers/rfq.ts` following the exact pattern of commitment.ts (protectedProcedure, loadProjectAbilities helper, audit logging).

**Procedures:**

1. **create** (mutation) - Create a new RFQ
   - Input: createRfqSchema from @construction/shared
   - Load project abilities, check `ability.can('create', 'RFQ')`
   - Generate sequential rfqNumber: query max existing rfqNumber for this project, parse the number, increment. Format: "RFQ-{NNN}" (e.g., RFQ-001, RFQ-002)
   - Insert into rfqs table with status='draft'
   - Audit log: action='rfq_created'
   - Return the created RFQ

2. **list** (query) - List RFQs for a project
   - Input: { projectId: uuid, status?: rfqStatusEnum optional }
   - Load project abilities, check `ability.can('read', 'RFQ')`
   - Query rfqs table with optional status filter, ordered by createdAt DESC
   - For each RFQ, include bid count (COUNT from bids table) and invitation count (COUNT from rfq_invitations)
   - Return array with metadata

3. **getById** (query) - Get RFQ with full details
   - Input: { id: uuid }
   - Load project abilities (lookup projectId from rfq first), check `ability.can('read', 'RFQ')`
   - Return RFQ with amendments (ordered by amendmentNumber), invitations (with subcontractor details via LEFT JOIN), and bid count

4. **update** (mutation) - Update RFQ (only draft status)
   - Input: updateRfqSchema from @construction/shared
   - Only allow updates when status='draft' (throw BAD_REQUEST otherwise with message "Only draft RFQs can be edited. Use amendments for issued RFQs.")
   - Audit log with before/after state

5. **issue** (mutation) - Issue an RFQ (change status to 'issued')
   - Input: { id: uuid }
   - Validate: must be 'draft' status, must have at least 1 invitation
   - Set status='issued', issuedAt=NOW(), issuedBy=userId
   - Audit log: action='rfq_issued'

6. **close** (mutation) - Close an RFQ (stop accepting bids)
   - Input: { id: uuid }
   - Validate: must be 'issued' status
   - Set status='closed', closedAt=NOW()
   - Audit log: action='rfq_closed'

7. **cancel** (mutation) - Cancel an RFQ
   - Input: { id: uuid }
   - Validate: must be 'draft' or 'issued' (not awarded/closed/cancelled)
   - Set status='cancelled'
   - Audit log: action='rfq_cancelled'

8. **createAmendment** (mutation) - Add amendment to issued RFQ
   - Input: createAmendmentSchema from @construction/shared
   - Validate: RFQ must be in 'issued' status (can't amend draft or closed)
   - Generate sequential amendmentNumber (query max for this rfqId, increment)
   - Insert into rfq_amendments
   - If dueDateChange provided, update rfqs.dueDate
   - If scopeChanges provided, update rfqs.scopeOfWork
   - Audit log: action='rfq_amended' with amendment details

9. **addInvitation** (mutation) - Invite a subcontractor to an RFQ
   - Input: createInvitationSchema from @construction/shared
   - Validate: RFQ status must be 'draft' or 'issued'
   - If subcontractorId provided, verify exists in subcontractor_directory
   - Check for duplicate invitation (same rfqId + subcontractorId, or same rfqId + externalEmail)
   - Insert into rfq_invitations with sentAt=NOW()
   - Audit log: action='rfq_invitation_sent'

10. **removeInvitation** (mutation) - Remove an invitation
    - Input: { id: uuid }
    - Validate: invitation status must be 'pending' (can't remove if already responded)
    - Delete from rfq_invitations
    - Audit log

11. **delete** (mutation) - Delete a draft RFQ
    - Input: { id: uuid }
    - Validate: status must be 'draft'
    - Delete from rfqs (cascade deletes amendments, invitations)
    - Audit log: action='rfq_deleted'

Use the same loadProjectAbilities pattern from budget.ts/commitment.ts. All mutations should audit log with before/after state using the pattern from commitment.ts.

**Create `apps/api/src/trpc/routers/subcontractor.ts`:**

Follow the same tRPC router pattern as other routers. This router does NOT need project-level abilities since the directory is company-wide (not project-scoped). Use protectedProcedure and check CASL abilities directly against 'SubcontractorDirectory' subject.

**Procedures:**

1. **create** (mutation) - Add subcontractor to directory
   - Input: createSubcontractorSchema from @construction/shared
   - Check `ability.can('create', 'SubcontractorDirectory')`
   - Insert into subcontractor_directory with status='active'
   - Audit log: action='subcontractor_created'
   - Return created record

2. **list** (query) - List subcontractors with filtering
   - Input: { status?: subcontractorStatusEnum optional, trade?: number optional (CSI division), search?: string optional }
   - Check `ability.can('read', 'SubcontractorDirectory')`
   - Query with filters:
     - status filter on status column
     - trade filter: use SQL to check if trades JSONB array contains the division number
     - search filter: ILIKE on companyName or contactName or contactEmail
   - Order by companyName ASC
   - Return array

3. **getById** (query) - Get subcontractor with bid history
   - Input: { id: uuid }
   - Check `ability.can('read', 'SubcontractorDirectory')`
   - Return subcontractor details
   - Include bid history: query bids table where subcontractorId matches, JOIN with rfqs for rfqNumber/title, JOIN bid_versions for latest amount. Return array of { rfqId, rfqNumber, rfqTitle, bidId, latestAmount, status, submittedAt }

4. **update** (mutation) - Update subcontractor info
   - Input: updateSubcontractorSchema from @construction/shared
   - Check `ability.can('update', 'SubcontractorDirectory')`
   - Audit log with before/after state
   - Return updated record

5. **delete** (mutation) - Remove from directory
   - Input: { id: uuid }
   - Check `ability.can('delete', 'SubcontractorDirectory')`
   - Check if subcontractor has any active bids (status = submitted or under_review). If yes, prevent deletion with message "Cannot delete subcontractor with active bids. Set status to inactive instead."
   - Delete record
   - Audit log

6. **getByTrades** (query) - Get subcontractors matching specific trades (for RFQ invitation helper)
   - Input: { trades: array of numbers (CSI divisions) }
   - Check `ability.can('read', 'SubcontractorDirectory')`
   - Query subcontractor_directory where trades JSONB array contains ANY of the provided divisions
   - Filter to status='active' only
   - Return array sorted by companyName
