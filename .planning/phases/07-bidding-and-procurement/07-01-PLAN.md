Add 7 new tables to `createTenantSchema()` in tenant.ts, following the exact pattern of existing tables (uuid PKs, text columns, timestamps with timezone, references with cascade/set null):

**1. subcontractor_directory** - Company's subcontractor contacts
- id: uuid PK defaultRandom
- companyName: text NOT NULL
- contactName: text
- contactEmail: text
- contactPhone: text
- address: text
- trades: jsonb NOT NULL default [] (array of CSI division numbers, same pattern as project costCodes)
- notes: text
- status: text NOT NULL default 'active' (active, inactive, blacklisted)
- createdBy: text NOT NULL
- createdAt: timestamp with timezone defaultNow NOT NULL
- updatedAt: timestamp with timezone defaultNow NOT NULL

**2. rfqs** - Request for Quotation
- id: uuid PK defaultRandom
- projectId: uuid NOT NULL references projects(id) ON DELETE CASCADE
- rfqNumber: text NOT NULL (sequential like "RFQ-001", generated server-side)
- title: text NOT NULL
- description: text
- scopeOfWork: text NOT NULL
- trades: jsonb NOT NULL default [] (CSI divisions this RFQ targets)
- dueDate: timestamp with timezone NOT NULL
- status: text NOT NULL default 'draft' (draft, issued, closed, awarded, cancelled)
- issuedAt: timestamp with timezone
- issuedBy: text
- closedAt: timestamp with timezone
- attachmentIds: jsonb default [] (references to document IDs for specs/drawings)
- createdBy: text NOT NULL
- createdAt: timestamp with timezone defaultNow NOT NULL
- updatedAt: timestamp with timezone defaultNow NOT NULL

**3. rfq_amendments** - Immutable amendment trail for RFQs
- id: uuid PK defaultRandom
- rfqId: uuid NOT NULL references rfqs(id) ON DELETE CASCADE
- amendmentNumber: integer NOT NULL (1, 2, 3...)
- description: text NOT NULL (what changed)
- scopeChanges: text (modified scope text, null if no scope change)
- dueDateChange: timestamp with timezone (new due date, null if no change)
- createdBy: text NOT NULL
- createdAt: timestamp with timezone defaultNow NOT NULL

**4. rfq_invitations** - Tracks which subs were invited to an RFQ
- id: uuid PK defaultRandom
- rfqId: uuid NOT NULL references rfqs(id) ON DELETE CASCADE
- subcontractorId: uuid references subcontractor_directory(id) ON DELETE SET NULL (null for external invites)
- externalEmail: text (for subs not in directory)
- externalCompanyName: text
- status: text NOT NULL default 'pending' (pending, viewed, responded, declined)
- sentAt: timestamp with timezone
- viewedAt: timestamp with timezone
- respondedAt: timestamp with timezone
- createdAt: timestamp with timezone defaultNow NOT NULL

**5. bids** - Bid submissions from subcontractors
- id: uuid PK defaultRandom
- rfqId: uuid NOT NULL references rfqs(id) ON DELETE CASCADE
- invitationId: uuid references rfq_invitations(id) ON DELETE SET NULL
- subcontractorId: uuid references subcontractor_directory(id) ON DELETE SET NULL
- bidderCompanyName: text NOT NULL (denormalized for history)
- bidderContactEmail: text
- currentVersionId: uuid (points to latest bid_versions record)
- status: text NOT NULL default 'submitted' (submitted, under_review, shortlisted, awarded, rejected, withdrawn)
- submittedAt: timestamp with timezone defaultNow NOT NULL
- awardedAt: timestamp with timezone
- awardedBy: text
- commitmentId: uuid (references commitments(id) once converted, nullable)
- notes: text
- createdAt: timestamp with timezone defaultNow NOT NULL
- updatedAt: timestamp with timezone defaultNow NOT NULL

**6. bid_versions** - Snapshot versioning for bids
- id: uuid PK defaultRandom
- bidId: uuid NOT NULL references bids(id) ON DELETE CASCADE
- versionNumber: integer NOT NULL (1, 2, 3...)
- totalAmount: numeric(15,2) NOT NULL
- lineItems: jsonb NOT NULL (array of {description, quantity, unitPrice, amount, costCodeId?})
- scopeNotes: text
- exclusions: text
- inclusions: text
- validUntil: timestamp with timezone
- submittedAt: timestamp with timezone defaultNow NOT NULL
- triggerAmendmentId: uuid references rfq_amendments(id) ON DELETE SET NULL (which amendment prompted this version, null for original)

**7. bid_leveling_notes** - Scope leveling annotations for bid comparison
- id: uuid PK defaultRandom
- rfqId: uuid NOT NULL references rfqs(id) ON DELETE CASCADE
- bidId: uuid NOT NULL references bids(id) ON DELETE CASCADE
- category: text NOT NULL (e.g., "scope_gap", "scope_extra", "clarification", "risk")
- note: text NOT NULL
- adjustmentAmount: numeric(15,2) (positive = add, negative = subtract for leveled comparison)
- createdBy: text NOT NULL
- createdAt: timestamp with timezone defaultNow NOT NULL

Update `provision.ts` with raw SQL CREATE TABLE statements for all 7 tables, following the exact same pattern as existing budget tables. Add indexes:

- idx_bids_rfq ON bids(rfq_id)
- idx_bid_versions_bid ON bid_versions(bid_id)

Update `context.ts` to expose all 7 new tables in the RequestTenantContext.schema object.

Note: commitmentId on bids is a TEXT reference (not FK) to commitments.id to avoid circular dependency complexity. Application-level validation ensures the commitment exists.

**Create `packages/shared/src/types/bidding.ts`** with Zod schemas and TypeScript types:

Enums:
- `rfqStatusEnum`: z.enum(["draft", "issued", "closed", "awarded", "cancelled"])
- `bidStatusEnum`: z.enum(["submitted", "under_review", "shortlisted", "awarded", "rejected", "withdrawn"])
- `invitationStatusEnum`: z.enum(["pending", "viewed", "responded", "declined"])
- `subcontractorStatusEnum`: z.enum(["active", "inactive", "blacklisted"])
- `levelingCategoryEnum`: z.enum(["scope_gap", "scope_extra", "clarification", "risk"])

Schemas:
- `createRfqSchema`: { projectId: uuid, title: string(1-200), description: string(max 5000) optional, scopeOfWork: string(1-10000), trades: array of numbers, dueDate: string (ISO date), attachmentIds: array of uuid strings optional }
- `updateRfqSchema`: { id: uuid, title: optional, description: optional nullable, scopeOfWork: optional, trades: optional, dueDate: optional, status: rfqStatusEnum optional }
- `createAmendmentSchema`: { rfqId: uuid, description: string(1-2000), scopeChanges: string optional, dueDateChange: string (ISO date) optional }
- `createInvitationSchema`: { rfqId: uuid, subcontractorId: uuid optional, externalEmail: email string optional, externalCompanyName: string optional } with refine: must have either subcontractorId OR (externalEmail AND externalCompanyName)
- `submitBidSchema`: { rfqId: uuid, invitationId: uuid optional, totalAmount: number positive, lineItems: array of { description: string, quantity: number optional, unitPrice: number optional, amount: number positive, costCodeId: number optional } min 1, scopeNotes: string optional, exclusions: string optional, inclusions: string optional, validUntil: string (ISO date) optional }
- `updateBidVersionSchema`: { bidId: uuid, totalAmount: number positive, lineItems: same as above, scopeNotes: optional, exclusions: optional, inclusions: optional, validUntil: optional, triggerAmendmentId: uuid optional }
- `createSubcontractorSchema`: { companyName: string(1-200), contactName: string optional, contactEmail: email optional, contactPhone: string optional, address: string optional, trades: array of numbers, notes: string optional }
- `updateSubcontractorSchema`: { id: uuid, companyName: optional, contactName: optional nullable, contactEmail: optional nullable, contactPhone: optional nullable, address: optional nullable, trades: optional, notes: optional nullable, status: subcontractorStatusEnum optional }
- `awardBidSchema`: { bidId: uuid, convertToCommitment: boolean default false, commitmentDescription: string optional }
- `createLevelingNoteSchema`: { rfqId: uuid, bidId: uuid, category: levelingCategoryEnum, note: string(1-2000), adjustmentAmount: number optional }

Interfaces:
- `BidComparisonRow`: { bidId, bidderCompanyName, totalAmount, leveledAmount, lineItems, exclusions, inclusions, scopeNotes, levelingNotes[], status }
- `RfqSummary`: { id, rfqNumber, title, status, dueDate, bidCount, invitationCount, projectId }
