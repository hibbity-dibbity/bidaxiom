  <action>
Create `apps/api/src/trpc/routers/bid.ts` following the commitment.ts pattern (protectedProcedure, loadProjectAbilities, audit logging).

**Procedures:**

1. **submit** (mutation) - Submit a new bid
   - Input: submitBidSchema from @construction/shared
   - Lookup RFQ to get projectId, load project abilities
   - Check `ability.can('create', 'Bid')`
   - Validate: RFQ status must be 'issued' (not draft, closed, cancelled, awarded)
   - If invitationId provided, validate it exists and belongs to this RFQ
   - Transaction:
     a. Insert into bids (status='submitted', submittedAt=NOW())
     b. Insert first bid_version (versionNumber=1, with lineItems, totalAmount, scopeNotes, exclusions, inclusions, validUntil)
     c. Update bids.currentVersionId to point to the new version
     d. If invitationId provided, update rfq_invitations.status='responded', respondedAt=NOW()
   - Audit log: action='bid_submitted'
   - Return bid with version

2. **updateVersion** (mutation) - Create a new version of an existing bid
   - Input: updateBidVersionSchema from @construction/shared
   - Lookup bid to get rfqId then projectId, load abilities
   - Check `ability.can('update', 'Bid')`
   - Validate: bid status must be 'submitted' or 'under_review' (can't update awarded/rejected/withdrawn)
   - Validate: RFQ must still be 'issued' (can't update bid on closed RFQ)
   - Transaction:
     a. Get max versionNumber for this bidId, increment
     b. Insert new bid_version
     c. Update bids.currentVersionId to new version
   - Audit log: action='bid_version_created'
   - Return updated bid with new version

3. **listByRfq** (query) - List all bids for an RFQ
   - Input: { rfqId: uuid, includeVersions?: boolean default false }
   - Lookup RFQ projectId, load abilities, check `ability.can('read', 'Bid')`
   - Query bids where rfqId matches, JOIN bid_versions for current version (totalAmount)
   - If includeVersions, also return all versions per bid
   - Order by submittedAt ASC
   - Return array

4. **getById** (query) - Get bid with all versions
   - Input: { id: uuid }
   - Lookup bid to get rfqId/projectId, load abilities
   - Check `ability.can('read', 'Bid')`
   - Return bid with ALL versions (ordered by versionNumber DESC), rfq details (title, rfqNumber, status), and any leveling notes

5. **compare** (query) - Side-by-side bid comparison for an RFQ
   - Input: { rfqId: uuid, bidIds?: array of uuid optional (if omitted, compare all non-withdrawn/rejected bids) }
   - Load abilities, check `ability.can('read', 'Bid')`
   - For each bid:
     a. Get current version (totalAmount, lineItems, exclusions, inclusions, scopeNotes)
     b. Get leveling notes for this bid
     c. Calculate leveledAmount = totalAmount + sum(adjustmentAmount from leveling notes where adjustmentAmount is not null)
   - Return array of BidComparisonRow objects sorted by leveledAmount ASC (lowest first)

6. **addLevelingNote** (mutation) - Add scope leveling annotation
   - Input: createLevelingNoteSchema from @construction/shared
   - Load abilities, check `ability.can('update', 'Bid')` (or manage RFQ - PM/estimator can level)
   - Insert into bid_leveling_notes
   - Audit log: action='bid_leveling_note_added'
   - Return created note

7. **removeLevelingNote** (mutation) - Remove a leveling note
   - Input: { id: uuid }
   - Lookup note to get rfqId/projectId, load abilities
   - Check ability
   - Delete from bid_leveling_notes
   - Audit log

8. **updateStatus** (mutation) - Change bid status (under_review, shortlisted, rejected, withdrawn)
   - Input: { id: uuid, status: bidStatusEnum }
   - Load abilities, check `ability.can('update', 'Bid')`
   - Validate transitions:
     - submitted -> under_review, shortlisted, rejected, withdrawn
     - under_review -> shortlisted, rejected, withdrawn
     - shortlisted -> awarded, rejected, withdrawn (awarded handled by award procedure)
     - awarded -> (terminal, no transitions except via separate process)
     - rejected -> (terminal)
     - withdrawn -> (terminal)
   - Cannot set status to 'awarded' via this procedure (use award procedure)
   - Update bid status
   - Audit log with before/after status

9. **award** (mutation) - Award a bid and optionally convert to commitment
   - Input: awardBidSchema from @construction/shared
   - Load abilities, check `ability.can('manage', 'RFQ')` (only PMs/admins can award)
   - Validate: bid status must be 'submitted', 'under_review', or 'shortlisted'
   - Validate: RFQ status must be 'issued' or 'closed'
   - Transaction:
     a. Set bid status='awarded', awardedAt=NOW(), awardedBy=userId
     b. Set RFQ status='awarded' (marks entire RFQ as having a winner)
     c. If convertToCommitment=true:
        - Get current bid version (totalAmount, lineItems)
        - Insert into commitments table: type='subcontract', vendorName=bid.bidderCompanyName, description=commitmentDescription or RFQ title, totalAmount from bid version, status='draft', projectId from RFQ
        - Insert commitment_line_items from bid line items (map costCodeId, description, amount)
        - Update bid.commitmentId with the new commitment ID
     d. Reject all other non-withdrawn bids for this RFQ (set status='rejected') - optional, controlled by a "rejectOthers" boolean param defaulting to true
   - Audit log: action='bid_awarded' with commitment details if converted
   - Return { bid, commitment? }

10. **getAmendmentNotifications** (query) - Check if bid needs updating after RFQ amendment
    - Input: { bidId: uuid }
    - Load abilities
    - Get bid's latest version triggerAmendmentId
    - Get all amendments for the bid's RFQ
    - If there are amendments newer than the bid's latest version (or triggerAmendmentId is null and amendments exist), return { hasUnacknowledgedAmendments: true, amendments: [...] }
    - Otherwise return { hasUnacknowledgedAmendments: false, amendments: [] }
  </action>
