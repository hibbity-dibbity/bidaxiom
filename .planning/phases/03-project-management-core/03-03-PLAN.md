Create `apps/api/src/trpc/routers/project.ts` with these procedures. Follow the patterns in `company.ts` for procedure structure (authorizedProcedure or protectedProcedure, explicit tenant/userId null checks for TypeScript, audit logging).

**Import from @construction/shared:** createProjectSchema, updateProjectSchema, teamMemberSchema, projectPhaseSchema, DEFAULT_PROJECT_FOLDERS, DEFAULT_PROJECT_PHASES, projectRoleEnum

**Procedures:**

1. **project.create** (protectedProcedure, input: createProjectSchema)
   - Check CASL: `throwUnlessCan("create", "Project")`
   - Use a database transaction to atomically:
     a. Insert into `projects` table with all fields from input. Set createdBy to ctx.userId.
     b. Auto-add the creating user as project_manager in `project_team_members` (the creator always has PM access)
     c. Insert additional team members from `input.teamMembers` into `project_team_members`
     d. Create default folder structure from DEFAULT_PROJECT_FOLDERS in `folders` table (all with parentId = null, projectId = new project's id)
     e. If `input.phases` provided, insert those. Otherwise, insert DEFAULT_PROJECT_PHASES.
   - After transaction, create audit log: entityType "Project", action "create", entityId = project.id
   - Return the created project with its id

2. **project.list** (protectedProcedure, input: z.object with optional filters)
   - Input: `{ status?: projectStatusEnum, search?: z.string().optional(), limit?: z.number().default(50), offset?: z.number().default(0) }`
   - Load user's CASL abilities with project team memberships (query project_team_members for ctx.userId to get their projectIds and roles)
   - Call `defineAbilitiesFor(role, userId, teamMemberships)` to build abilities
   - For org:admin: return all projects matching filters
   - For other roles: only return projects where user is a team member (use the projectIds from team membership query as a WHERE IN condition)
   - Order by createdAt desc
   - Return `{ items: Project[], total: number }`

3. **project.getById** (protectedProcedure, input: z.object({ id: z.string().uuid() }))
   - Query project by id
   - Check CASL: `throwUnlessCan("read", "Project", { id: project.id })`
   - Also query project's team members (JOIN with user_profiles on clerk_user_id to get names/emails)
   - Also query project's phases (ordered by orderIndex)
   - Return project with teamMembers array and phases array

4. **project.update** (protectedProcedure, input: updateProjectSchema)
   - Query project first to verify it exists
   - Check CASL: `throwUnlessCan("update", "Project", { id: input.id })`
   - Update only the provided fields (use a spread of only defined fields)
   - Set updatedAt to now
   - Audit log: action "update", changes: { before: oldProject, after: updatedProject }
   - Return updated project

5. **project.archive** (protectedProcedure, input: z.object({ id: z.string().uuid() }))
   - Check CASL: `throwUnlessCan("delete", "Project", { id: input.id })`
   - Soft delete: set status to "archived", set updatedAt
   - Audit log: action "archive"
   - Return { success: true }

6. **project.addTeamMember** (protectedProcedure, input: z.object({ projectId: z.string().uuid(), userId: z.string().min(1), role: projectRoleEnum }))
   - Check CASL: `throwUnlessCan("manage", "ProjectTeam", { projectId: input.projectId })`
   - Insert into project_team_members
   - Audit log: action "add_team_member", entityType "ProjectTeam"
   - Return the new team member record

7. **project.removeTeamMember** (protectedProcedure, input: z.object({ projectId: z.string().uuid(), userId: z.string().min(1) }))
   - Check CASL: `throwUnlessCan("manage", "ProjectTeam", { projectId: input.projectId })`
   - Delete from project_team_members WHERE projectId AND userId match
   - Audit log: action "remove_team_member"
   - Return { success: true }

8. **project.updatePhases** (protectedProcedure, input: z.object({ projectId: z.string().uuid(), phases: z.array(projectPhaseSchema) }))
   - Check CASL: `throwUnlessCan("update", "Project", { id: input.projectId })`
   - In a transaction: delete existing phases for projectId, insert new phases
   - Audit log: action "update_phases"
   - Return updated phases

**Important patterns to follow:**
- Use `protectedProcedure` (not authorizedProcedure) because we need to manually load project team memberships before building abilities
- For project.list: query the user's team memberships first, then build abilities, then filter
- For mutations: query the user's team memberships, build abilities with `defineAbilitiesFor(role, userId, memberships)`, then check permissions
- All mutations must audit log. Use `createAuditLog()` helper (fire-and-forget, never throws)
- Handle TypeScript null checks for ctx.tenant and ctx.userId with explicit runtime guards (same pattern as company.ts)

**Loading abilities with project context:**
For procedures that need project-level CASL checks, add a helper function at the top of the file:

```typescript
async function loadProjectAbilities(ctx: { tenant: NonNullable<...>, userId: string, orgRole: string }) {
  const memberships = await ctx.tenant.db
    .select({ projectId: ctx.tenant.schema.projectTeamMembers.projectId, role: ctx.tenant.schema.projectTeamMembers.role })
    .from(ctx.tenant.schema.projectTeamMembers)
    .where(eq(ctx.tenant.schema.projectTeamMembers.userId, ctx.userId));

  return defineAbilitiesFor(ctx.orgRole, ctx.userId, memberships);
}
```

Note: ctx.orgRole comes from the Clerk JWT org role. Check the tRPC context.ts to see how the org role is stored — it may be at `ctx.orgRole` or similar. If it's not available, read it from the tRPC context file and use whatever field stores the Clerk org role.
