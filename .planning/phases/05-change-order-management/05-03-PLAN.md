- Props: `{ projectId: string }`
- Query: `trpc.changeOrder.list.useQuery({ projectId, status: filterStatus, type: filterType })`
- Filters:
  - Status dropdown: All, Draft, PCO Submitted, Pending Approval, Approved, Rejected, Void
  - Type dropdown: All, Owner, Internal, Subcontractor
- Table/card layout showing for each CO:
  - PCO/CO number (show CO number if approved, else PCO number if submitted, else "Draft")
  - Title (truncated to ~60 chars)
  - Type badge: owner=blue, internal=amber, subcontractor=purple
  - Status badge: draft=gray, pco_submitted=yellow, pending_approval=orange, approved=green, rejected=red, void=slate
  - Total amount (formatted with Intl.NumberFormat USD)
  - Created date
  - Click navigates to detail page: `/projects/${projectId}/change-orders/${co.id}`
- "New Change Order" button links to `/projects/${projectId}/change-orders/new`
- Empty state: "No change orders yet. Create your first change order above."
- Loading state: skeleton cards (same pattern as commitment-list.tsx)

**Create `change-order-form.tsx`:**
- Props: `{ projectId: string }`
- Multi-step form using react-hook-form + zodResolver:
  - **Step 1: Type Selection** - Three radio cards: Owner, Internal, Subcontractor
    - Owner: "Change requested by the project owner"
    - Internal: "Change identified internally (errors, efficiency, value engineering)"
    - Subcontractor: "Change to a subcontract or purchase order"
  - **Step 2: Details** - Dynamic fields based on selected type:
    - Common: title, description
    - Owner: requestedBy (text input)
    - Internal: reason (select: Error, Efficiency, Value Engineering, Other)
    - Subcontractor: commitmentId (select dropdown populated from `trpc.commitment.list.useQuery({ projectId, status: 'executed' })`)
  - **Step 3: Line Items** - Dynamic array using useFieldArray:
    - Budget line item select (optional, populated from `trpc.budget.listLineItems.useQuery({ projectId })`)
    - Cost code (auto-fills from selected budget line item, or manual entry)
    - Description (auto-fills or manual)
    - Amount change (number input, can be negative)
    - Add/remove line item buttons
    - Running total displayed at bottom
  - **Submit:** Calls `trpc.changeOrder.create.useMutation()`
  - On success: toast "Change order created" + navigate to detail page
  - On error: toast error message
- Currency formatting: same pattern as commitment-form.tsx (Intl.NumberFormat)
- Form validation: use createChangeOrderSchema for the selected type variant

**Create `change-order-detail.tsx`:**
- Props: `{ changeOrderId: string, projectId: string }`
- Query: `trpc.changeOrder.getById.useQuery({ id: changeOrderId })`
- Layout sections:
  1. **Header:** PCO/CO number (large), title, status badge, type badge
  2. **Action buttons** (conditional on status):
     - Draft: "Edit" (link to edit page or inline edit), "Submit for Approval" (dialog), "Delete" (confirmation dialog)
     - Rejected: "Edit & Resubmit"
     - Approved: "Void" (confirmation dialog with reason input)
  3. **Details card:** Description, type-specific fields (requestedBy for owner, reason for internal, commitment reference for subcontractor), related documents
  4. **Line items table:** Cost code, description, amount change (green for +, red for -), budget line item reference
  5. **Summary:** Total amount change (bold, color-coded)
  6. **Approval panel:** `<ApprovalPanel>` component (see below)
  7. **History timeline:** `<ChangeOrderHistory>` component (see below)

- **Submit for approval dialog:**
  - Uses `trpc.changeOrder.submit.useMutation()`
  - Simple approval chain builder:
    - Add steps with step order (auto-incremented)
    - Each step: select approver role (dropdown: Project Manager, Superintendent, Accountant, Admin) OR specific user
    - Minimum 1 step required
  - On submit: toast "Submitted for approval" + invalidate queries

- **Delete confirmation:** Uses `trpc.changeOrder.delete.useMutation()`, only shown for draft status

- **Void confirmation:** Dialog with reason text input, uses `trpc.changeOrder.void.useMutation()`

**Create `approval-panel.tsx`:**
- Props: `{ changeOrderId: string }`
- Query: `trpc.changeOrder.getApprovalStatus.useQuery({ changeOrderId })`
- Only render when CO status is pco_submitted, pending_approval, approved, or rejected
- Display as a vertical stepper/timeline:
  - Each step shows: step number, approver role or user, status icon
  - Pending: circle outline (gray)
  - Approved: checkmark circle (green) with approver name and timestamp
  - Rejected: X circle (red) with rejector name and reason
  - Skipped: dash circle (gray)
- **Current step highlight:** If user can approve at current step (canCurrentUserApprove from API), show prominent "Approve" and "Reject" buttons
  - Approve: calls `trpc.changeOrder.approve.useMutation({ changeOrderId, comments })`
  - Reject: opens dialog for rejection reason, calls `trpc.changeOrder.reject.useMutation({ changeOrderId, comments })`
  - Comments text area (optional for approve, recommended for reject)
- On approve/reject: invalidate changeOrder.getById, changeOrder.getApprovalStatus, changeOrder.list

**Create `change-order-history.tsx`:**
- Props: `{ changeOrderId: string }`
- Query: `trpc.changeOrder.getHistory.useQuery({ changeOrderId })`
- Display as reverse-chronological timeline (most recent first)
- Each entry shows:
  - Timestamp (relative: "2 hours ago", absolute on hover)
  - User who made the change (changedBy)
  - Change type icon:
    - field_update: pencil icon
    - status_change: arrow-right icon
    - approval: check-circle or x-circle icon
    - line_item_change: list icon
  - Description:
    - field_update: "Changed {fieldName} from {oldValue} to {newValue}"
    - status_change: "Status changed from {old} to {new}"
    - approval: "Approved/Rejected at step {N}" with comments
    - line_item_change: "Updated line items (revision {N})"
  - Comments (if any)
- Revision numbers shown as badges: "Rev. 1", "Rev. 2", etc.
- Empty state: "No history yet"
