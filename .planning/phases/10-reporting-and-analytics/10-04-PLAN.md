Create apps/api/src/services/report-scheduler.ts with scheduling logic:

**calculateNextRun function:**
- Accept: schedule (ReportSchedule)
- Based on frequency, calculate next run timestamp:
  - 'daily' → tomorrow at schedule.time
  - 'weekly' → next occurrence of schedule.dayOfWeek at schedule.time
  - 'monthly' → next occurrence of schedule.dayOfMonth at schedule.time (handle end-of-month edge cases: day 31 in 30-day months)
  - 'quarterly' → next quarter boundary (Jan 1, Apr 1, Jul 1, Oct 1) at schedule.time
- Return Date object

**processSchedule function:**
- Accept: db, schema, schedule, reportDefinition
- Execute report via executeReport service
- Export report via exportReport service using schedule.format
- Send email via sendReportEmail with attachment
- Update schedule.lastRunAt = NOW(), schedule.nextRunAt = calculateNextRun(schedule)
- Return { success: boolean, error?: string }

Create apps/api/src/services/email-sender.ts with email delivery:

**sendReportEmail function:**
- Accept: recipients (string[]), subject, bodyHtml, attachmentPath, attachmentFilename
- Create nodemailer transport with SMTP config from env:
  - host: process.env.SMTP_HOST
  - port: process.env.SMTP_PORT
  - auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS }
- Send email with:
  - from: process.env.SMTP_FROM
  - to: recipients.join(', ')
  - subject: subject
  - html: bodyHtml
  - attachments: [{ filename: attachmentFilename, path: attachmentPath }]
- Return { success: boolean, messageId?: string, error?: string }

**buildReportEmailHtml function:**
- Accept: reportDefinition, downloadUrl
- Return HTML email template with:
  - Report title and description
  - Generated date/time
  - Filters applied summary
  - Download link (if downloadUrl provided)
  - Company branding placeholder
- Use simple inline CSS for email client compatibility

Create apps/api/src/jobs/scheduled-reports.ts with BullMQ queue:

**scheduledReportsQueue:**
- Use BullMQ Queue constructor
- Queue name: 'scheduled-reports'
- Connection: Redis from env (REDIS_HOST, REDIS_PORT)

**startScheduledReportsWorker function:**
- Create BullMQ Worker
- Worker name: 'scheduled-reports'
- Process function:
  - Extract scheduleId from job.data
  - Load schedule and report definition from database
  - Call processSchedule service
  - If success, log completion
  - If failure, throw error for retry
- Retry config: { attempts: 3, backoff: { type: 'exponential', delay: 5000 } }
- On failure after retries, log error to console

**scheduleNextReports function:**
- Query all active schedules where nextRunAt <= NOW()
- For each schedule, add job to queue
- Update schedule.nextRunAt to avoid duplicate scheduling

Create apps/api/src/trpc/routers/report-schedule.ts with schedule CRUD:

**Procedures:**

1. **list** - Query
   - Input: z.object({ reportDefinitionId (optional), isActive (boolean optional) })
   - Returns schedules filtered by reportDefinitionId and/or isActive
   - Include report definition name in response
   - Order by nextRunAt ASC

2. **getById** - Query
   - Input: z.object({ id })
   - Returns full schedule with report definition
   - Verify user has read access to associated Report

3. **create** - Mutation (requires manage Report)
   - Input: reportScheduleSchema (without id, timestamps, lastRunAt, nextRunAt)
   - Validates:
     - reportDefinitionId exists
     - recipients array not empty
     - time is valid HH:MM format
     - dayOfWeek (0-6) if frequency is weekly
     - dayOfMonth (1-31) if frequency is monthly
   - Calculates nextRunAt using calculateNextRun
   - Inserts schedule
   - Adds job to BullMQ queue if nextRunAt <= NOW() + 1 hour
   - Returns created schedule with nextRunAt
   - Audit logs creation

4. **update** - Mutation (requires manage Report)
   - Input: z.object({ id, ...partial reportScheduleSchema })
   - Updates schedule
   - Recalculates nextRunAt if frequency, dayOfWeek, dayOfMonth, or time changed
   - Updates queue job if active
   - Audit logs change

5. **delete** - Mutation (requires manage Report)
   - Input: z.object({ id })
   - Deletes schedule
   - Removes pending jobs from queue
   - Audit logs deletion

6. **toggleActive** - Mutation (requires manage Report)
   - Input: z.object({ id, isActive (boolean) })
   - Updates schedule.isActive
   - If activating, adds job to queue
   - If deactivating, removes jobs from queue
   - Audit logs toggle

7. **runNow** - Mutation (requires manage Report)
   - Input: z.object({ id })
   - Loads schedule
   - Adds immediate job to BullMQ queue (bypasses nextRunAt check)
   - Returns { success: true, message: 'Report scheduled for immediate delivery' }
   - Audit logs manual run
