**apps/web/middleware.ts** (NEW):
- Import { NextResponse } from "next/server"
- Export middleware function accepting request
- Read theme cookie: request.cookies.get("theme")?.value
- If theme cookie exists and is "dark" or "light":
  - Clone response
  - Set x-theme header for debugging
  - Return response
- Else return NextResponse.next()
- Export config matcher: { matcher: ["/((?!api|_next/static|_next/image|favicon.ico).*)"] }

**apps/web/app/providers.tsx** (UPDATE):
- Import ThemeProvider from "@/components/providers/theme-provider"
- Wrap entire return statement in ThemeProvider BEFORE AuthProvider:
  ```tsx
  return (
    <ThemeProvider>
      <AuthProvider initialSession={initialSession}>
        <TrpcAndAbilityProvider>{children}</TrpcAndAbilityProvider>
      </AuthProvider>
    </ThemeProvider>
  );
  ```

Why cookie-based:
- Server-rendered HTML reads cookie in middleware to apply correct theme class
- Prevents FOUC by ensuring SSR matches client hydration
- next-themes handles cookie storage automatically when storageKey is set

Why NOT localStorage:
- localStorage is client-only, causes FOUC on SSR
- Research findings (13-CONTEXT.md) identify this as CRITICAL
