  <action>
    Install svix in apps/api for Clerk webhook verification: npm install svix

    apps/api/src/tenant/provision.ts:
    - Export async function provisionTenantSchema(orgId: string, orgName: string, pool: Pool)
    - Generate schema name: "tenant_" + orgId.replace('org_', '') (sanitize to lowercase alphanumeric + underscore only)
    - Use PostgreSQL advisory lock to prevent race conditions:
      1. Hash orgId to integer for pg_advisory_lock
      2. SELECT pg_advisory_lock(hash)
      3. Check if tenant already exists in public.tenants (idempotent)
      4. If exists, return existing tenant record
      5. If not: BEGIN transaction
         - CREATE SCHEMA IF NOT EXISTS "schema_name"
         - Create audit_logs table (id uuid PK, entity_type text, entity_id text, action text, actor_id text, actor_email text, changes jsonb, ip_address text, timestamp timestamptz default now())
         - Create user_profiles table (id uuid PK, clerk_user_id text unique not null, email text, first_name text, last_name text, role text default 'member', created_at timestamptz, updated_at timestamptz)
         - REVOKE UPDATE, DELETE ON audit_logs FROM PUBLIC (immutable)
         - GRANT INSERT, SELECT ON audit_logs TO current_user
         - INSERT into public.tenants (schema_name, clerk_org_id, name, status='active')
         - COMMIT
      6. SELECT pg_advisory_unlock(hash)
    - Handle errors: ROLLBACK on failure, always release advisory lock in finally block
    - Return the tenant record { id, schemaName, clerkOrgId, name }

    apps/api/src/tenant/resolve.ts:
    - Export async function resolveTenant(clerkOrgId: string): Promise<TenantRecord | null>
    - Query public.tenants WHERE clerk_org_id = clerkOrgId AND status = 'active'
    - Return null if not found (caller decides how to handle)
    - Type TenantRecord: { id: string, schemaName: string, clerkOrgId: string, name: string, status: string }

    apps/api/src/tenant/context.ts:
    - Export async function buildTenantContext(clerkOrgId: string, clerkUserId: string): Promise<TenantContext>
    - Steps:
      1. Resolve tenant via resolveTenant(clerkOrgId)
      2. If not found, throw error with code 'TENANT_NOT_FOUND'
      3. Create scoped DB client: createTenantDb(tenant.schemaName)
      4. Return { tenantId: tenant.id, schemaName: tenant.schemaName, companyName: tenant.name, db: scopedDb, userId: clerkUserId }
    - NEVER store tenant context in global/module scope — always return fresh per request
    - NEVER derive tenant ID from frontend request — always from authenticated Clerk session

    Update apps/api/src/db/migrate.ts:
    - Add the tenant schema table creation SQL as a reusable function (used by provision.ts)
    - Keep the existing public schema migration
  </action>

    apps/api/src/webhooks/clerk.ts:
    - Import Webhook from 'svix' for signature verification
    - Export async function handleClerkWebhook(req: { body: string, headers: Record<string, string> })
    - Verify webhook signature using svix with CLERK_WEBHOOK_SECRET
    - Handle event types:

      organization.created:
      - Extract org id, name from event data
      - Call provisionTenantSchema(org.id, org.name, pool)
      - Log success: "Provisioned schema for org {id}"
      - Return { success: true, schemaName }

      organizationMembership.created:
      - Extract organization.id, public_user_data.user_id from event data
      - Resolve tenant via resolveTenant(organization.id)
      - Insert into user_company_mappings (public schema): { clerkUserId, tenantId, role: membership.role }
      - Insert into tenant schema user_profiles: { clerkUserId, email, firstName, lastName, role }
      - Log: "User {userId} joined org {orgId}"

      organizationMembership.deleted:
      - Extract organization.id, public_user_data.user_id
      - Remove from user_company_mappings
      - Update user_profiles in tenant schema (mark as inactive or delete)
      - Log: "User {userId} left org {orgId}"

    - For unhandled event types, return { success: true, message: 'Event type not handled' }
    - Wrap in try/catch, return 500 on verification failure, 200 on success

    apps/api/src/webhooks/routes.ts:
    - Register webhook route on Fastify: POST /api/webhooks/clerk
    - Parse raw body (important: svix needs raw body string for verification)
    - Configure Fastify to NOT parse JSON on this route (use addContentTypeParser for raw body)
    - Call handleClerkWebhook and return response

    apps/web/app/api/webhooks/clerk/route.ts:
    - Alternative: If webhooks hit the Next.js app instead of Fastify, create a Next.js API route
    - POST handler that forwards to the same handleClerkWebhook logic
    - Use headers() to extract svix headers
    - Return NextResponse with appropriate status
    - NOTE: Decide based on deployment — if webhook URL is the Next.js app, use this route. If Fastify, use the Fastify route. Implement BOTH so either works.

    Register the webhook routes in apps/api/src/server.ts.
