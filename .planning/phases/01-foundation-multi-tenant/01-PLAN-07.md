<objective>
Implement immutable audit logging for sensitive actions. Create an audit logger that writes to tenant-scoped audit_logs tables, a tRPC middleware for automatic logging, and a query API for viewing audit history.

Purpose: IDMT-09 requires "Sensitive actions (financial changes, bid submissions, schedule updates) are immutably audit-logged." This is a compliance requirement. Audit logs must be tamper-proof (no UPDATE/DELETE) and capture full change history.
Output: Audit logging service, tRPC middleware for automatic logging, audit log query router.
</objective>

    apps/api/src/audit/types.ts:
    - Import AuditAction from @construction/shared
    - Export AuditLogInput type: {
        entityType: string (e.g., 'Project', 'Budget', 'Bid', 'PayApplication', 'ChangeOrder')
        entityId: string
        action: AuditAction
        actorId: string
        actorEmail?: string
        changes: { before?: Record<string, unknown>, after?: Record<string, unknown> }
        ipAddress?: string
        metadata?: Record<string, unknown> (extra context like "approved by", "reason")
      }
    - Export AuditLogQuery type: {
        entityType?: string
        entityId?: string
        action?: AuditAction
        actorId?: string
        startDate?: Date
        endDate?: Date
        limit?: number (default 50, max 200)
        offset?: number (default 0)
      }
    - Export SENSITIVE_ACTIONS constant: list of actions that MUST be audit-logged:
      [FINANCIAL_CHANGE, BID_SUBMIT, SCHEDULE_UPDATE, ROLE_CHANGE, DELETE, CREATE (for financial entities)]

    apps/api/src/audit/logger.ts:
    - Export class AuditLogger:
      - constructor(tenantDb: TenantDb) — receives scoped Drizzle instance
      - async log(input: AuditLogInput): Promise<void>
        - INSERT into audit_logs table with all fields
        - MUST NOT throw on failure — log errors but don't break the main operation
        - Use try/catch internally, log error to console/monitoring
      - async query(params: AuditLogQuery): Promise<AuditLogEntry[]>
        - Build dynamic WHERE clause from params
        - Order by timestamp DESC
        - Apply limit/offset for pagination
        - Return typed AuditLogEntry array
      - async getEntityHistory(entityType: string, entityId: string): Promise<AuditLogEntry[]>
        - Convenience method: get all logs for a specific entity
        - Ordered by timestamp ASC (chronological)

    - Export factory function createAuditLog(tenantDb, input): Promise<void>
      - Shorthand for new AuditLogger(tenantDb).log(input)

    apps/api/src/trpc/middleware/audit.ts:
    - Export function withAuditLog(config: { entityType: string, action: AuditAction }) middleware:
      1. Runs the procedure (next())
      2. AFTER success (not before), creates audit log entry:
         - entityType from config
         - entityId from procedure result (if result has .id)
         - action from config
         - actorId from ctx.userId
         - changes: { input: procedure input, output: procedure result } (sanitized)
         - ipAddress from request headers if available
      3. On procedure failure, still log the ATTEMPT with error details (for security auditing)
      4. NEVER block the response waiting for audit log write — fire and forget OR use Promise.allSettled

    - Export function auditSensitiveAction(action: AuditAction) — shorthand middleware that auto-detects entityType from procedure path

    Verify audit_logs table schema in tenant.ts includes all needed columns.
    Verify migrate.ts REVOKE UPDATE, DELETE is applied during schema provisioning.

    IMPORTANT: Audit log writes must NEVER fail the parent operation. If audit log insertion fails, the original action should still succeed. Log the audit failure separately.
  </action>
  <verify>
    1. `npx tsc --noEmit` — no errors
    2. Create test tenant schema, call createAuditLog() — row inserted into audit_logs
    3. Attempt UPDATE on audit_logs — should fail (permission revoked)
    4. Attempt DELETE on audit_logs — should fail (permission revoked)
    5. AuditLogger.query() with filters returns correct results
    6. AuditLogger.getEntityHistory() returns chronological history
    7. withAuditLog middleware logs after successful procedure execution
  </verify>
  <done>
