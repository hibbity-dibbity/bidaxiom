  <action>
Create `apps/api/src/trpc/routers/dashboard.ts` with the following endpoints using `protectedProcedure` (not `authorizedProcedure` — dashboard is read-only and scoped by tenant context, no CASL needed):

Import from existing modules:
- `router`, `protectedProcedure` from `../trpc.js` and `../procedures.js`
- `TRPCError` from `@trpc/server`
- `eq`, `and`, `sql`, `count` from `drizzle-orm`

**User-scoped endpoints** (filter by `ctx.userId` via projectTeamMembers join):

1. `myActiveProjects` — Query: JOIN projects with projectTeamMembers WHERE userId = ctx.userId AND projects.status = 'active'. Return `{ count: number, overdueCount: number }`. Overdue = endDate < NOW() AND status = 'active'. Use `sql<number>\`COUNT(DISTINCT ...)\`` pattern. Handle null ctx.tenant by returning `{ count: 0, overdueCount: 0 }`.

2. `myOpenBids` — Query: JOIN bids with rfqs with projectTeamMembers WHERE userId = ctx.userId AND bids.status IN ('submitted', 'under_review', 'shortlisted'). Return `{ count: number }`. If user has no team memberships, return 0.

3. `myTodo` — Proxy data approach (no task table exists). Count pending approval items assigned to the current user across three sources:
   - Change order approval steps: WHERE approverUserId = ctx.userId AND status = 'pending'
   - Payment app approval steps: WHERE approverUserId = ctx.userId AND status = 'pending'
   - Workflow approvals: WHERE approverUserId = ctx.userId AND status = 'pending'
   Return `{ count: number, breakdown: { changeOrders: number, paymentApps: number, workflows: number } }`.

**Company-scoped endpoints** (no user filter, just tenant schema scope):

4. `totalActiveProjects` — COUNT projects WHERE status = 'active'. Return `{ count: number }`.

5. `openBids` — COUNT bids WHERE status IN ('submitted', 'under_review', 'shortlisted'). Return `{ count: number }`.

6. `pendingPayApps` — COUNT paymentApps WHERE status IN ('submitted', 'under_review'). Return `{ count: number, totalAmount: number }`. totalAmount = SUM of currentPaymentDue.

7. `bidOpportunities` — COUNT rfqs WHERE status = 'issued' (open RFQs awaiting bids). Return `{ count: number }`.

8. `revenueInProgress` — SUM budgetLineItems.budgetedAmount for all active projects (JOIN with projects WHERE status = 'active'). Return `{ total: number }`. Use COALESCE for null safety. Parse numeric string to float.

9. `backlog` — Total committed but unearned revenue: SUM of commitments.totalAmount WHERE status IN ('approved', 'executed') for active projects minus SUM of paymentApps.totalCompletedAndStored for active projects. Return `{ total: number }`. If no data, return 0.

10. `estimatingPipeline` — Placeholder for Phase 17-18. Return `{ total: 0, hasEstimatingModule: false }` always. No database query needed.

**Important patterns:**
- Guard with `if (!ctx.tenant) throw new TRPCError({ code: "INTERNAL_SERVER_ERROR" })` at the top of each procedure
- Extract `const { db, schema } = ctx.tenant` for clean access
- Use `sql<number>` for aggregation type safety
- Use `COALESCE(SUM(...), 0)` for null-safe aggregations
- Parse string results from NUMERIC columns with `parseFloat()` or `Number()`
- Follow existing audit.summary pattern for structure
