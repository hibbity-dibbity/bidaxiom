  <action>
Update `apps/api/src/db/schema/tenant.ts` — add four new tables inside `createTenantSchema()`:

1. **qboConnections** table:
   - `id`: uuid, primaryKey, defaultRandom
   - `realmId`: text, notNull (QBO company ID from OAuth callback)
   - `environment`: text, notNull (sandbox | production)
   - `accessToken`: text (short-lived, 1 hour — OK unencrypted)
   - `encryptedRefreshToken`: text, notNull (AES-256-GCM encrypted)
   - `tokenExpiresAt`: timestamp with timezone, notNull
   - `refreshTokenExpiresAt`: timestamp with timezone, notNull
   - `companyName`: text (QBO company display name)
   - `status`: text, notNull, default "active" (active | disconnected | expired | error)
   - `lastSyncAt`: timestamp with timezone
   - `errorMessage`: text
   - `connectedBy`: text, notNull (Clerk user ID who connected)
   - `createdAt`: timestamp with timezone, defaultNow, notNull
   - `updatedAt`: timestamp with timezone, defaultNow, notNull

2. **qboSyncState** table:
   - `id`: uuid, primaryKey, defaultRandom
   - `entityType`: text, notNull (project, invoice, bill, payment, vendor, customer)
   - `lastSuccessfulSync`: timestamp with timezone
   - `lastCdcSync`: timestamp with timezone
   - `syncStatus`: text, notNull, default "pending"
   - `errorMessage`: text
   - `syncedCount`: integer, notNull, default 0
   - `errorCount`: integer, notNull, default 0
   - `updatedAt`: timestamp with timezone, defaultNow, notNull

3. **qboEntityMappings** table:
   - `id`: uuid, primaryKey, defaultRandom
   - `entityType`: text, notNull
   - `platformId`: uuid, notNull (our entity ID)
   - `qboId`: text, notNull (QBO entity ID — string, not integer)
   - `qboSyncToken`: text (QBO's optimistic lock token)
   - `direction`: text, notNull, default "bidirectional"
   - `lastSyncedAt`: timestamp with timezone
   - `syncStatus`: text, notNull, default "synced"
   - `metadata`: jsonb, default {}
   - `createdAt`: timestamp with timezone, defaultNow, notNull
   - `updatedAt`: timestamp with timezone, defaultNow, notNull

4. **qboSyncNotifications** table:
   - `id`: uuid, primaryKey, defaultRandom
   - `entityType`: text, notNull (project, invoice, bill, payment, vendor, customer)
   - `entityId`: text (platform or QBO ID of the failed entity, nullable)
   - `message`: text, notNull (human-readable error description)
   - `severity`: text, notNull, default "error" (error | warning | info)
   - `dismissed`: boolean, notNull, default false
   - `createdAt`: timestamp with timezone, defaultNow, notNull

Purpose: When the BullMQ worker exhausts all retry attempts for a sync job, it inserts a notification record here. The UI polls these to show user-facing alerts about sync failures that need attention.

Add all four to the return object of `createTenantSchema()`.

Update `apps/api/src/tenant/provision.ts` — add SQL CREATE TABLE statements for all four tables BEFORE the `INSERT INTO tenants` statement. Follow the exact same pattern as existing tables (using `"${schemaName}".table_name`). Add indexes:
   - `idx_qbo_connections_realm` on qbo_connections(realm_id) — for webhook lookup by realmId
   - `idx_qbo_entity_mappings_platform` on qbo_entity_mappings(entity_type, platform_id) — for forward mapping
   - `idx_qbo_entity_mappings_qbo` on qbo_entity_mappings(entity_type, qbo_id) — for reverse mapping
   - `UNIQUE(entity_type, platform_id)` constraint on qbo_entity_mappings — one mapping per entity
   - `UNIQUE(entity_type, qbo_id)` constraint on qbo_entity_mappings — prevent duplicate QBO references

Note: Do NOT add foreign key from qbo_entity_mappings.platformId to projects/commitments etc. The entity type is polymorphic (could be project, invoice, bill) so we use application-level validation instead.
