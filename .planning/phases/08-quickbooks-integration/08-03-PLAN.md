**`apps/api/src/integrations/quickbooks/sync/mappers/project.ts`:**

Platform Project maps to QBO Customer entity.

`syncProjectToQbo(params)`:
- Accepts: `{ tenantId, projectId, db, schema, qboClient }` where db and schema come from tenant context and qboClient is a node-quickbooks instance.
- Look up qbo_entity_mappings for this projectId + entityType='project'.
- If no mapping exists: CREATE new QBO Customer with `DisplayName: project.name`, `CompanyName: project.name`, `Notes: "Platform Project ID: {projectId}"`. Store mapping with qboId, qboSyncToken, direction='bidirectional'.
- If mapping exists: SPARSE UPDATE QBO Customer — send only Id, SyncToken (from mapping), sparse: true, and changed fields (DisplayName). Store new SyncToken.
- Catch SyncToken conflicts (code 5010) and delegate to handleSyncTokenConflict.
- Use `promisifyQbo` to wrap callback-style node-quickbooks methods.

`syncProjectFromQbo(params)`:
- Accepts: `{ tenantId, qboId, db, schema, qboClient }`
- Fetch Customer from QBO by Id.
- Look up qbo_entity_mappings for this qboId + entityType='project'.
- If mapping exists: update platform project name to match QBO DisplayName. Update mapping's qboSyncToken.
- If no mapping: create new project record in platform from QBO Customer data. Create mapping.
- Handle inactive QBO entities (Active: false) by marking mapping syncStatus as 'deleted'.

**`apps/api/src/integrations/quickbooks/sync/workers.ts`:**

Create the BullMQ Worker that processes sync jobs:

```typescript
import { Worker } from 'bullmq';
```

Export `startQboSyncWorker(): Worker` function that creates and returns a Worker:
- Queue name: 'qbo-sync' (must match queue.ts)
- Connection: import `redisConnection` from queue.ts
- Concurrency: 10 (matches QBO concurrent request limit)
- Limiter: { max: 400, duration: 60000 } (400 jobs/min, buffer under QBO's 500/min)

Worker processor function:
1. Extract `{ tenantId, entityType, platformId, qboId, operation, syncReason }` from job.data (QboSyncJobData type).
2. Build tenant context: use `resolveTenant(tenantId)` and `buildTenantContext()` to get `db` and `schema` (import from tenant modules).
3. Get QBO connection from qbo_connections table for this tenant. If no active connection, skip job silently.
4. Check if access token is expired (tokenExpiresAt < now). If expired, call `refreshQboToken()`, update stored tokens in qbo_connections.
5. Create QBO client via `createQboClient(accessToken, realmId)`.
6. Determine sync direction from job.name: 'sync-to-qbo' or 'sync-from-qbo'.
7. Call `dispatchSync(direction, entityType, { tenantId, db, schema, qboClient, platformId, qboId })`.
8. On success: update qbo_sync_state for this entityType — set lastSuccessfulSync to now, increment syncedCount.
9. On error: handle specific error types:
   - Rate limit (429): throw to trigger BullMQ retry with backoff
   - Auth error (401): attempt token refresh once, then throw if still failing
   - SyncToken conflict (5010): handle via conflict.ts, do NOT retry (user must resolve)
   - Other errors: throw to trigger retry

Add worker event handlers:
- `on('completed')`: log success
- `on('failed')`: log error; if `job.attemptsMade >= job.opts.attempts`, update qbo_sync_state with errorMessage and increment errorCount

**`apps/api/src/integrations/quickbooks/cdc.ts`:**

Export `runCdcForTenant(tenantId: string): Promise<void>`:
1. Get QBO connection for tenant. If not active, return.
2. Get qbo_sync_state to find lastCdcSync timestamp.
3. Calculate changedSince: use lastCdcSync or default to 24 hours ago. Max lookback: 30 days (QBO CDC limit).
4. Create QBO client.
5. For each entity type ['Customer', 'Invoice', 'Bill', 'Payment']:
   - Call QBO CDC endpoint: `/company/{realmId}/cdc?entities={entityType}&changedSince={ISO_timestamp}`
   - Use `promisifyQbo` to make the API call. node-quickbooks may not have a CDC helper — use makeApiCall or direct fetch if needed.
   - Parse CDCResponse[0].QueryResponse[0][entityType] to get changed entities.
   - For each changed entity, add job to qboSyncQueue with `{ tenantId, entityType: entity.name.toLowerCase(), qboId: entity.Id, syncReason: 'cdc' }`.
6. Update qbo_sync_state lastCdcSync to now.
7. Wrap each entity type query in try/catch — continue with others if one fails.
8. Log summary: "CDC: Found N changed {EntityType} for tenant {tenantId}".

Export `runCdcForAllTenants(): Promise<void>`:
- Query public.tenants table for all active tenants.
- For each tenant, check if qbo_connections exists and is active.
- Call runCdcForTenant for each connected tenant.
- This function is designed to be called from a daily cron/scheduler (not implemented here — just the function).
