**2. `handleCallback` (mutation, protected):**
- Use `protectedProcedure` (callback comes from QBO redirect, user is authenticated but may not have abilities loaded).
- Input: `z.object({ code: z.string(), realmId: z.string(), state: z.string() })`.
- Action:
  - Verify `state` matches current tenantId (prevents CSRF).
  - Call `handleQboCallback(code, realmId, tenantId)` to exchange code for tokens.
  - Encrypt refresh token via `encryptToken(tokens.refreshToken)`.
  - Insert record into qbo_connections table with all token fields, realmId, environment, connectedBy=userId, status='active'.
  - Initialize qbo_sync_state rows for each entity type (project, invoice, bill, payment, vendor, customer) with status='pending'.

**3. `disconnect` (mutation, authorized — admin only):**
- Check `abilities.can('manage', 'QuickBooks')`.
- Input: none.
- Action:
  - Update qbo_connections status to 'disconnected', clear accessToken and encryptedRefreshToken.
  - Audit log: action='quickbooks_disconnected'.
- Return `{ success: true }`.

**4. `getStatus` (query, authorized — admin or accountant):**
- Check `abilities.can('read', 'QuickBooks')`.
- Input: none.
- Action:
  - Query qbo_connections for this tenant. If none, return `{ connected: false }`.
  - Query all qbo_sync_state rows for this tenant.
  - Return `{ connected: boolean, connection: { realmId, companyName, status, lastSyncAt, environment, connectedBy, refreshTokenExpiresAt }, syncStates: Array<{ entityType, lastSuccessfulSync, syncStatus, syncedCount, errorCount, errorMessage }> }`.

  - If specific entityType: query platform entities of that type without mappings and queue sync jobs.
  - For entities with existing mappings, also queue sync-to-qbo jobs (to push updates).
  - Update qbo_sync_state for the entity type to 'syncing'.
  - Return `{ jobsQueued: number }`.

**`apps/api/src/integrations/quickbooks/webhooks.ts`:**

Create CloudEvents webhook handler (MANDATORY format by May 15, 2026 per research):

Export `handleQboWebhook(payload: unknown, signature: string): Promise<{ processed: number }>`:
1. Verify webhook signature using HMAC-SHA256:
   - Use `QBO_WEBHOOK_VERIFIER_TOKEN` from environment.
   - Compute HMAC-SHA256 of raw payload body using the verifier token as key.
   - Compare Base64-encoded hash with `Intuit-Signature` header value.
   - Throw if mismatch.
2. Parse payload using Zod cloudEventSchema:
   ```typescript
   const cloudEventSchema = z.object({
     specversion: z.literal('1.0'),
     type: z.string(),
     source: z.string(),
     id: z.string(),
     time: z.string(),
     datacontenttype: z.literal('application/json'),
     data: z.object({
       realmId: z.string(),
       entities: z.array(z.object({
         name: z.string(),
         id: z.string(),
         operation: z.enum(['Create', 'Update', 'Delete', 'Void']),
         lastUpdated: z.string(),
       })),
     }),
   });
   ```
3. Find tenant by realmId: query `qbo_connections` across all tenant schemas (query public.tenants first, then check each tenant's qbo_connections for matching realmId). If not found, log warning and return `{ processed: 0 }`.
4. For each entity in data.entities, map entity.name to our entityType (Customer->project, Invoice->invoice, Bill->bill, Payment->payment). Skip unknown entity types.
5. Queue sync-from-qbo job for each relevant entity via `qboSyncQueue.add('sync-from-qbo', { tenantId, entityType, qboId: entity.id, operation: entity.operation, syncReason: 'webhook' })`.
6. Return `{ processed: entities.length }`.

**Update `apps/api/src/webhooks/routes.ts`:**

Add QBO webhook route inside the existing webhookRoutes plugin function. Add it AFTER the Clerk webhook route:

```typescript
fastify.post("/api/integrations/quickbooks/webhook", async (request, reply) => {
  try {
    const body = typeof request.body === 'string' ? request.body : JSON.stringify(request.body);
    const signature = request.headers['intuit-signature'] as string || '';

    const result = await handleQboWebhook(body, signature);
    return reply.status(200).send(result);
  } catch (err) {
    const message = err instanceof Error ? err.message : 'Unknown webhook error';
    if (message.includes('Invalid webhook signature')) {
      return reply.status(401).send({ error: 'Invalid signature' });
    }
    console.error('QBO webhook error:', err);
    return reply.status(500).send({ error: message });
  }
});
```

Import `handleQboWebhook` from the webhooks module. This works in the existing scoped plugin — the raw body parser (already registered for Clerk) will also handle QBO webhook payloads.

Also add the OAuth callback route as a plain Fastify route (not tRPC, because QBO redirects here with query params):

```typescript
fastify.get("/api/integrations/quickbooks/callback", async (request, reply) => {
  const { code, realmId, state } = request.query as { code: string; realmId: string; state: string };
  // Redirect to frontend with params (frontend will call tRPC handleCallback)
  const frontendUrl = process.env.CORS_ORIGIN || 'http://localhost:3000';
  return reply.redirect(`${frontendUrl}/settings/integrations/quickbooks/callback?code=${code}&realmId=${realmId}&state=${state}`);
});
```

This redirect pattern means the OAuth callback goes to QBO -> API -> Frontend. The frontend page then calls the tRPC `handleCallback` mutation with the code and realmId. This keeps the tRPC mutation authenticated (user's Clerk session is active in browser).
