# Phase 38 Plan 04: Change Order PDF — Template, Procedure, and UI Button Summary

**One-liner:** AIA-format Change Order PDF template with inline signature blocks, status gate tRPC procedure, and "Generate PDF" button in the CO detail page that saves to the document library.

## What Was Built

Implemented the full Change Order PDF feature (PDF-02) end-to-end:

1. **`apps/api/src/pdf/templates/change-order.ts`** — Complete HTML template exporting `buildChangeOrderHtml(data: ChangeOrderPdfData)`:
   - Header: company name, "CHANGE ORDER" label, CO number, status badge with color-coded status (Approved=green, Pending Approval=amber, Draft/others=slate), generated date
   - Project details section: project name, job number, address (3-column grid)
   - CO description section: title (bold) + description paragraph
   - Cost breakdown table: Description / Amount Change columns
   - Contract sum impact summary: Original Contract Sum, This Change Order, Revised Contract Sum (BIDAXIOM blue total row)
   - Schedule impact section: shows "No schedule impact" or "{N} days" (field not in schema, always null)
   - AIA-format signature blocks: 3-column layout — Owner, Contractor, Architect/Engineer — each with signature line, Name, Title, Date printed placeholders
   - Footer: "Generated by BIDAXIOM — {date}"
   - All user strings passed through `escapeHtml()` for XSS safety

2. **`pdf.generateChangeOrder` in `apps/api/src/trpc/routers/pdf.ts`** — Full tRPC mutation:
   - Input: `{ projectSlug: string, changeOrderId: UUID }`
   - Status gate: allows "pco_submitted", "pending_approval", "approved"; throws FORBIDDEN for draft/rejected/void
   - Fetches CO line items, project (budget for contract sum calculation), company name from public.tenants
   - Increments "change_order" document sequence counter
   - Resolves file name from naming settings or default template
   - Maps schema statuses to display labels ("pco_submitted" → "Pending Approval")
   - Computes contractSumBefore/After from project.budget (shows "N/A" if no budget)
   - Saves to document library with category "change_order"
   - Returns `{ documentId, fileName, message }`

3. **"Generate PDF" button in `apps/web/components/change-order/change-order-detail.tsx`**:
   - `canGeneratePdf` flag: true for `pco_submitted`, `pending_approval`, `approved`
   - `trpc.pdf.generateChangeOrder.useMutation` with success/error toasts
   - Button label: "Generate PDF" (FileDown icon); shows "Generating..." during pending
   - Button disabled while mutation is pending
   - Matches existing `variant="outline" size="sm"` button pattern in the page

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Schema Mismatch] Adapted line item data model to actual DB schema**
- **Found during:** Task 1, reviewing `change_order_line_items` schema
- **Issue:** Plan's `ChangeOrderPdfData.lineItems` interface specified `costType`, `quantity`, `unit`, `unitCost`, `total` fields. The actual schema only stores `description`, `costCodeId`, `amountChange`. There is no qty/unit/unitCost breakdown.
- **Fix:** Simplified `lineItems` to `{ description, amountChange }` matching the schema. Template renders "Amount Change" column. No cost-type subtotals since the schema has no costType on line items.
- **Files modified:** `apps/api/src/pdf/templates/change-order.ts`, `apps/api/src/trpc/routers/pdf.ts`
- **Commit:** 3fc3ec8

**2. [Rule 1 - Schema Mismatch] scheduleImpact field absent from schema**
- **Found during:** Task 1, reviewing `change_orders` schema
- **Issue:** Plan specified `scheduleImpactDays` as coming from the CO. The `change_orders` table has no such column.
- **Fix:** `scheduleImpactDays` always set to `null` in the procedure (matching the interface's `null` case). Template shows "No schedule impact". The interface retains the field for future use when the column is added.
- **Files modified:** `apps/api/src/trpc/routers/pdf.ts`
- **Commit:** 3fc3ec8

**3. [Rule 1 - Status Values] Status gate adapted to real CO status workflow**
- **Found during:** Task 1, reviewing change_orders.status values
- **Issue:** Plan said "status is 'pending' or 'approved'". Real statuses are: `draft`, `pco_submitted`, `pending_approval`, `approved`, `rejected`, `void`.
- **Fix:** Gate allows `["pco_submitted", "pending_approval", "approved"]`. Button `canGeneratePdf` uses the same three values. Matches semantic intent of the plan.
- **Files modified:** `apps/api/src/trpc/routers/pdf.ts`, `apps/web/components/change-order/change-order-detail.tsx`
- **Commit:** 3fc3ec8, 87fec23
