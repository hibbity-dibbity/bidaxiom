    **Create `apps/api/src/pdf/templates/rfq.ts`:**

    Export `buildRfqHtml(data: RfqPdfData): string`.

    RfqPdfData interface:
    ```typescript
    interface RfqPdfData {
      companyName: string;
      projectName: string;
      jobNumber: string | null;
      projectAddress: string;
      rfqTitle: string;
      rfqNumber: string;        // e.g., "RFQ-001" (if rfqs have a number field) or just sequential
      scopeOfWork: string;      // Free-text block from rfqs.scopeOfWork
      dueDate: string | null;   // rfqs.dueDate formatted as "February 25, 2026" or "Not specified"
      generatedDate: string;
      notes: string | null;     // rfqs.notes if the field exists, otherwise omit
    }
    ```

    Check the actual RFQ schema fields in tenant.ts before building the interface — use whatever fields exist (dueDate, scopeOfWork, etc.). Do NOT fabricate fields that don't exist in the schema.

    HTML template requirements:
    - All styles inline — no external CSS
    - Header: company name, "REQUEST FOR QUOTATION" document type label, RFQ number, date
    - Project info section: project name, job number, project address
    - "Scope of Work" section: render `scopeOfWork` as a formatted text block with proper white-space handling (`white-space: pre-wrap` so line breaks in the text are preserved)
    - Submission deadline: "Please submit your quotation by: [dueDate]" — if null, show "Submission deadline: To be confirmed"
    - Payment terms section: "Payment Terms: Net 30 from receipt of approved invoice" (standard hardcoded value since paymentTerms field does not exist in schema per research — add a TODO comment)
    - Response instructions section: brief standard text instructing subcontractors to include their company name, license number, and total bid amount
    - Signature/response block at bottom: subcontractor response area with "Company Name:", "License #:", "Total Bid Amount:", "Authorized Signature:", "Date:" fields as printed placeholders
    - Brand colors: slate-blue `#3B5BDB` header
    - Footer: "Issued by [companyName] | Generated by BIDAXIOM"

    **Add `generateRfq` to `apps/api/src/trpc/routers/pdf.ts`:**

    Input schema:
    ```typescript
    z.object({
      projectSlug: z.string(),
      rfqId: z.string().uuid(),
    })
    ```

    Procedure implementation:
    1. Look up project by slug.
    2. Look up RFQ by id. Verify it belongs to this project. Throw NOT_FOUND if missing.
    3. Get company name from `public.tenants`.
    4. Get `documentNamingSettings` from companyProfile (validTo IS NULL).
    5. Call `getNextDocumentSequence(db, schema, tenantId, "rfq")`.
    6. Call `resolveFileName(documentNamingSettings, "rfq", project.jobNumber, project.name, seq)`.
    7. Build `RfqPdfData` using actual RFQ schema fields. For `rfqNumber`, use the sequence number: `RFQ-${seq.toString().padStart(3, '0')}`.
    8. Call `buildRfqHtml(data)`.
    9. Call `generatePdfBuffer(html)`.
    10. Call `uploadPdfAndSave({ ..., category: "rfq", description: `RFQ: ${rfq.title || rfq.description || 'Request for Quotation'}` })`.
    11. Return `{ documentId, fileName, message: "RFQ PDF generated successfully" }`.

    Important: Read the actual RFQ fields from the rfqs table in tenant.ts (look for `title`, `description`, `dueDate`, `scopeOfWork` or equivalent). Do not assume field names — verify them from the schema.
