**Create `apps/api/src/trpc/routers/invoice-tracking.ts`:**

Build the invoice tracking router. This is a READ-ONLY router (no mutations) that generates reports from existing payment app and commitment data:

**Procedures:**

1. **getARAgingReport** (query):
   - Input: { asOfDate?: string } (defaults to now)
   - AR = money owed TO the company (approved payment apps not yet paid)
   - Use PostgreSQL EXTRACT and CASE for efficient bucket calculation:
   ```sql
   SELECT
     pa.id,
     pa.application_number,
     p.name AS project_name,
     p.id AS project_id,
     pa.current_payment_due,
     pa.approved_at,
     EXTRACT(DAY FROM ({asOfDate}::timestamp - pa.approved_at)) AS days_outstanding,
     CASE
       WHEN EXTRACT(DAY FROM ({asOfDate}::timestamp - pa.approved_at)) <= 30 THEN 'current'
       WHEN EXTRACT(DAY FROM ({asOfDate}::timestamp - pa.approved_at)) <= 60 THEN 'days31_60'
       WHEN EXTRACT(DAY FROM ({asOfDate}::timestamp - pa.approved_at)) <= 90 THEN 'days61_90'
       WHEN EXTRACT(DAY FROM ({asOfDate}::timestamp - pa.approved_at)) <= 120 THEN 'days91_120'
       ELSE 'days120Plus'
     END AS aging_bucket
   FROM payment_apps pa
   INNER JOIN projects p ON p.id = pa.project_id
   WHERE pa.status = 'approved' AND pa.paid_at IS NULL
   ```
   - Group results by project for the byProject breakdown
   - Return ARAgingReport interface shape (from shared types)

2. **getAPAgingReport** (query):
   - Input: { asOfDate?: string }
   - AP = money the company OWES to vendors (approved commitments not fully paid)
   - Use commitments table (from Phase 4) with status='approved' or 'executed'
   - Commitments have a vendorName field (or partyName) — group by vendor
   - Use similar EXTRACT/CASE pattern as AR but with commitment approved dates
   - Note: commitments may not have an "approvedAt" field in the current schema. If not, use createdAt as fallback. Check the actual commitment schema and use the most appropriate date field.
   - Return APAgingReport interface shape (from shared types)

3. **getPaymentHistory** (query):
   - Input: { projectId }
   - Return all payment apps for the project with status, amount, dates
   - Ordered by applicationNumber ASC (chronological)
   - Include cumulative totals: running sum of currentPaymentDue, running retainage held
   - Useful for payment history chart

4. **getCashFlowSummary** (query):
   - Input: { projectId? } (optional — if omitted, return company-wide summary)
   - Return:
     - totalReceivable: sum of approved unpaid payment apps
     - totalPayable: sum of approved unpaid commitments
     - netCashPosition: totalReceivable - totalPayable
     - totalRetainageHeld: sum of retainage with status='held'
     - overdueReceivable: sum of approved unpaid payment apps with days > 30
     - overduePayable: sum of approved unpaid commitments with days > 30
