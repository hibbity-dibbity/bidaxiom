**Replace with:**
```typescript
// Update budget actuals and lock line items
// This implements PYMT-06: approved payment apps update budget actualCost
for (const lineItem of lineItems) {
  if (lineItem.budgetLineItemId) {
    // Calculate actual cost for this payment period (work this period + materials stored)
    const workThisPeriod =
      ((Number(lineItem.currentPercentComplete) - Number(lineItem.previousPercentComplete)) / 100)
      * Number(lineItem.scheduledValue);
    const materialsStored = Number(lineItem.materialsStored ?? 0);
    const actualCostThisPeriod = workThisPeriod + materialsStored;

    // Increment actualCost atomically using SQL expression (prevents race conditions)
    await tx
      .update(schema.budgetLineItems)
      .set({
        actualCost: sql`${schema.budgetLineItems.actualCost} + ${actualCostThisPeriod}`,
        isLocked: true,
        lockedAt: new Date(),
        lockedBy: userId,
        updatedAt: new Date(),
      })
      .where(eq(schema.budgetLineItems.id, lineItem.budgetLineItemId));
  }
}
```

**Why this approach:**
- Atomic increment: `sql\`actualCost + ${amount}\`` prevents race conditions (similar to Phase 5 budget updates)
- Work this period calculation: Matches G703 formula used in frontend (06-04-SUMMARY.md line 192)
- Materials stored: Adds stored materials to actual cost per AIA G703 standard
- Combined with locking: Single UPDATE statement updates both actualCost and locking fields
- Budget dashboard will now show actual costs: Queries can display actualCost vs budgetedAmount
