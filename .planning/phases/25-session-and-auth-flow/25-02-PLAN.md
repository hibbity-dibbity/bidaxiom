<objective>
Fix SESS-01: Users are proactively redirected to sign-in when their JWT session expires, not silently stuck on a stale page.

Purpose: The iron-session cookie lives 7 days but the JWT access token inside it expires every 15 minutes. Middleware only checks `session.userId` (present 7 days), so expired JWTs are never caught by middleware. Users only discover logout when a tRPC call fails. This plan adds two complementary layers: a proactive session watcher hook (catches expiry when user returns to a stale tab) and a reactive tRPC 401 interceptor (catches the race condition where the JWT expires exactly when a request fires).

Output:
- `use-session-watcher.ts` — hook checking JWT expiry on visibility-change + every 5min
- `(dashboard)/layout.tsx` — updated to mount the watcher for all authenticated pages
- `providers.tsx` — tRPC httpBatchLink with custom fetch that redirects on HTTP 401
</objective>

  <name>Task 2: Add tRPC 401 reactive interceptor to providers.tsx</name>

  <action>
    Update `apps/web/app/providers.tsx` — add a custom `fetch` function to `httpBatchLink`.

    The current `httpBatchLink` config has only `url` and `headers()`. Add a third property `fetch`:

    ```typescript
    async fetch(url, options) {
      const response = await globalThis.fetch(url, options);
      if (response.status === 401 && typeof window !== "undefined" && window.location.pathname !== "/sign-in") {
        const returnUrl = encodeURIComponent(window.location.pathname + window.location.search);
        window.location.href = `/sign-in?redirect_url=${returnUrl}`;
      }
      return response;
    },
    ```

    Key implementation notes:
    - Use `globalThis.fetch` inside the custom fetch to avoid infinite recursion (calling `fetch` would call itself)
    - Guard with `window.location.pathname !== "/sign-in"` to prevent redirect loops when the sign-in page itself makes an auth call
    - Guard with `typeof window !== "undefined"` for SSR safety
    - Use `window.location.href` (full page reload) NOT `router.push` — this re-runs middleware so iron-session is fully re-evaluated; client-side navigation leaves the broken session cookie in place
    - Do NOT clone the response before returning — just return the original `response` object; the response body is read by tRPC after this interceptor returns

    The complete updated `httpBatchLink` call should look like:
    ```typescript
    httpBatchLink({
      url: `${process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:3001"}/trpc`,
      async headers() {
        try {
          const res = await fetch("/api/auth/token");
          if (res.ok) {
            const { accessToken } = await res.json();
            return accessToken ? { Authorization: `Bearer ${accessToken}` } : {};
          }
        } catch {}
        return {};
      },
      async fetch(url, options) {
        const response = await globalThis.fetch(url, options);
        if (
          response.status === 401 &&
          typeof window !== "undefined" &&
          window.location.pathname !== "/sign-in"
        ) {
          const returnUrl = encodeURIComponent(window.location.pathname + window.location.search);
          window.location.href = `/sign-in?redirect_url=${returnUrl}`;
        }
        return response;
      },
    }),
    ```

    Do not change anything else in `providers.tsx`.
