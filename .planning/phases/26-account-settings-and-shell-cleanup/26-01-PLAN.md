<task type="auto">
  <name>Task 1: Add auth.changePassword mutation</name>
  <files>apps/api/src/trpc/routers/auth.ts</files>
  <action>
    Append a `changePassword` mutation to `authRouter` (before the closing `}`).

    Pattern: Follow the same manual Bearer token verification pattern used by `setupMfa` and `verifyMfaSetup` — extract Authorization header, call `verifyAccessToken`, then operate on the user.

    Input schema (zod):
    - `currentPassword: z.string()` — the user's existing password
    - `newPassword: z.string().min(8).regex(/[A-Z]/).regex(/[a-z]/).regex(/[0-9]/)` — same constraints as register/resetPassword

    Implementation steps:
    1. Extract Bearer token from `ctx.req.headers.authorization`, throw UNAUTHORIZED if missing or invalid
    2. Query `users` table by `payload.userId`
    3. Call `verifyPassword(user.passwordHash, input.currentPassword, user.hashType)` — throw UNAUTHORIZED with message "Current password is incorrect" if `valid` is false
    4. Call `hashPassword(input.newPassword)` to get `newPasswordHash`
    5. Update users table: `passwordHash: newPasswordHash, hashType: "argon2id"` where `id = payload.userId`
    6. Revoke all refresh tokens for this user (security — same pattern as `resetPassword`): update `refreshTokens` set `revokedAt = new Date()` where `userId = payload.userId`
    7. Return `{ success: true }`

    Do NOT send an email notification (out of scope for this phase).
    Do NOT invalidate the current access token — the user stays logged in on the current device but all refresh tokens are revoked (they will be prompted to re-login on other devices on next refresh).
  </action>
  <verify>
    TypeScript compiles without errors: `cd apps/api && npx tsc --noEmit 2>&1 | head -20`
    Grep confirms the mutation exists: `grep -n "changePassword" apps/api/src/trpc/routers/auth.ts`
  </verify>
  <done>auth.changePassword appears in authRouter, TypeScript compiles cleanly, the mutation verifies current password before updating and revokes refresh tokens on success</done>

<task type="auto">
  <name>Task 2: Add auth.disableMfa mutation</name>
  <files>apps/api/src/trpc/routers/auth.ts</files>
  <action>
    Append a `disableMfa` mutation to `authRouter` (after `changePassword`, before the closing `}`).

    Pattern: Same manual Bearer token verification as `setupMfa`/`changePassword`.

    Input schema (zod):
    - `currentPassword: z.string()` — require password confirmation before disabling MFA (security best practice)

    Implementation steps:
    1. Extract Bearer token from `ctx.req.headers.authorization`, throw UNAUTHORIZED if missing or invalid
    2. Query `users` table by `payload.userId`
    3. If `!user.mfaEnabled`, throw BAD_REQUEST with message "MFA is not currently enabled"
    4. Call `verifyPassword(user.passwordHash, input.currentPassword, user.hashType)` — throw UNAUTHORIZED with message "Current password is incorrect" if `valid` is false
    5. Update users table: `mfaEnabled: false, mfaSecret: null, mfaBackupCodes: null` where `id = payload.userId`
    6. Return `{ success: true }`

    The Drizzle schema columns `mfaSecret` and `mfaBackupCodes` are nullable — set them to `null` directly (no special handling needed).
    Do NOT revoke refresh tokens on MFA disable — this is intentional, the user stays logged in.
  </action>
  <verify>

  </verify>
