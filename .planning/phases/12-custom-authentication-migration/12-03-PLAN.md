Create a new organization router that replaces both the existing `tenantRouter` (org listing/switching) and the invitation part of `userRouter` (Clerk invitations). This router handles its own auth by verifying access tokens directly (since existing procedures still use Clerk).

**Helper: Create a lightweight auth middleware for this router.**

Since we can't use the existing `authProcedure` (it depends on Clerk), create a helper function at the top of the file:

```typescript
async function requireCustomAuth(ctx: Context): Promise<{ userId: string }> {
  const authHeader = ctx.req?.headers['authorization'];
  const token = typeof authHeader === 'string' ? authHeader.replace('Bearer ', '') : '';
  if (!token) throw new TRPCError({ code: 'UNAUTHORIZED', message: 'Authentication required' });

  const payload = await verifyAccessToken(token);
  return { userId: payload.userId };
}
```

Or, create a reusable middleware/procedure that verifies our custom JWT. This will be temporary -- Plan 05 replaces the main context.ts to use custom JWT natively.

**Procedures:**

1. `create` (mutation):
   - Input: `{ name: string, slug?: string }` (auto-generate slug from name if not provided, using kebab-case + random suffix for uniqueness)
   - Verify auth via custom JWT
   - Create organization record in `organizations` table
   - Generate a clerkOrgId-compatible identifier (e.g., `org_${nanoid(24)}`) for backward compatibility with existing `tenants.clerk_org_id` column
   - Call `provisionTenantSchema(orgId, name, pool)` to create tenant schema
   - Link: set `organizations.tenantId` to the provisioned tenant's ID
   - Create `organizationMemberships` record with role `org:admin` for the creating user
   - Also insert into legacy `userCompanyMappings` table (for backward compat until Plan 05 migrates away from it)
   - Create initial user_profile in tenant schema (matching existing lazy-sync pattern)
   - Return `{ id, name, slug, tenantId }`

2. `list` (query):
   - Verify auth via custom JWT
   - Query `organizationMemberships` joined with `organizations` for the current user
   - Return array of `{ id, name, slug, role, tenantId }`

3. `getById` (query):
   - Input: `{ organizationId: string }`
   - Verify auth + membership
   - Return org details including member count

4. `updateMemberRole` (mutation):
   - Input: `{ organizationId: string, userId: string, role: string }`
   - Verify auth + admin role in org
   - Validate role is one of: org:admin, org:member, org:project_manager, org:accountant, org:estimator, org:superintendent, org:foreman
   - Update membership role
   - Also update the user_profile role in tenant schema for consistency
   - Return updated membership

5. `removeMember` (mutation):
   - Input: `{ organizationId: string, userId: string }`
   - Verify auth + admin role
   - Cannot remove yourself if you're the last admin
   - Delete from `organizationMemberships`
   - Delete from legacy `userCompanyMappings`
   - Delete user_profile from tenant schema
   - Return `{ success: true }`

6. `listMembers` (query):
   - Input: `{ organizationId: string }`
   - Verify auth + membership
   - Join `organizationMemberships` with `users` to get member details
   - Return array of `{ userId, email, firstName, lastName, role, joinedAt }`

7. `invite` (mutation):
   - Input: `{ organizationId: string, email: string, role: string }`
   - Verify auth + admin role
   - Check email not already a member
   - Check no pending invitation for same email+org
   - Generate invitation token with `generateToken()`
   - Store hashed token in `organizationInvitations` with 7-day expiry
   - Send invitation email via `sendInvitationEmail()`
   - Return `{ invitationId, email, expiresAt }`

8. `listInvitations` (query):
   - Input: `{ organizationId: string }`
   - Verify auth + admin role
   - Return pending invitations with `{ id, email, role, expiresAt, createdAt }`

9. `revokeInvitation` (mutation):
   - Input: `{ invitationId: string }`
   - Verify auth + admin role in the invitation's org
   - Update invitation status to 'revoked'
   - Return `{ success: true }`

**Important notes:**
- Use the public schema `db` for all queries (NOT tenant DB)
- For tenant schema operations (creating user_profile), use `createTenantDb(schemaName)` pattern
- The `pg.Pool` for provisioning: import from `apps/api/src/db/client.ts` (the lazy pool)
- Slug generation: lowercase, replace spaces with hyphens, strip non-alphanumeric, append 6-char nanoid suffix for uniqueness
