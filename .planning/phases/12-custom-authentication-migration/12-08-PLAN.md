  <files>

  <action>
Create a migration script `apps/api/src/migrate-auth.ts` that migrates existing data from Clerk-era tables to the new auth tables. This script is designed to be run ONCE during the migration.

**What it does:**

1. **Create auth tables** in the public schema (call `provisionAuthTables()` if it exists, or run CREATE TABLE IF NOT EXISTS SQL directly).

2. **Migrate organizations**: For each row in `tenants` table:
   - Create a corresponding `organizations` record
   - Set `organizations.clerkOrgId = tenants.clerk_org_id` (for tracking)
   - Set `organizations.tenantId = tenants.id`
   - Generate a slug from the org name

3. **Migrate users**: For each unique `clerk_user_id` in `user_company_mappings`:
   - Create a `users` record with:
     - `clerkUserId = clerk_user_id` (for tracking)
     - `email` from tenant's user_profiles table (query any tenant where this user exists)
     - `firstName`, `lastName` from user_profiles
     - `passwordHash`: Set a placeholder. Since we can't export Clerk password hashes in development (requires Clerk support ticket for production export), set `hashType = 'none'` and `passwordHash = 'MIGRATION_PENDING'`. Users will need to use "Forgot Password" to set a new password. Document this in the migration output.
     - `emailVerified = true` (Clerk users were already verified)
     - `mfaEnabled = false` (Clerk MFA secrets are not exportable; users must re-setup)

4. **Migrate memberships**: For each row in `user_company_mappings`:
   - Find the corresponding `users` record (by clerkUserId)
   - Find the corresponding `organizations` record (by tenantId)
   - Create `organizationMemberships` record with the role

5. **Output migration report**:
   - Number of organizations migrated
   - Number of users migrated
   - Number of memberships migrated
   - List of users who need to reset passwords
   - Note about MFA re-setup requirement

**Script structure:**
```typescript
import dotenv from "dotenv";
dotenv.config({ path: "../../.env.local" });

import { db } from "./db/client.js";
import { tenants, userCompanyMappings, users, organizations, organizationMemberships } from "./db/schema/public.js";
// ... migration logic
```

Run with: `cd apps/api && npx tsx src/migrate-auth.ts`

**Important:**
- Script is idempotent (uses INSERT ... ON CONFLICT DO NOTHING)
- Script runs in a transaction
- Script logs progress to console
- This is a development convenience script. In production, Clerk provides user export CSVs with bcrypt hashes -- the script should be extended to import those when available.
