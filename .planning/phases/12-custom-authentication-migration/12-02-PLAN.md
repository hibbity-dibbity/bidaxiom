**Create `apps/api/src/services/email.ts`:**

Email service using Resend (per research recommendation). Include fallback behavior when RESEND_API_KEY is not set (log to console in development -- don't block auth flows during dev).

Functions:
- `sendVerificationEmail(email: string, token: string)`: Sends email with verification link `{APP_URL}/verify-email?token={token}`. Subject: "Verify your email address".
- `sendPasswordResetEmail(email: string, token: string)`: Sends email with reset link `{APP_URL}/reset-password?token={token}`. Subject: "Reset your password". Include 1-hour expiry notice.
- `sendInvitationEmail(email: string, orgName: string, inviterName: string, token: string)`: Sends email with invitation link `{APP_URL}/sign-up?invitation={token}`. Subject: "You've been invited to join {orgName}".
- All emails use APP_URL from `process.env.NEXT_PUBLIC_APP_URL || "http://localhost:3000"`.
- When RESEND_API_KEY is not configured, log the email content to console with `[EMAIL DEV]` prefix and return success (allows development without email service).

**Create `apps/api/src/trpc/routers/auth.ts`:**

Auth router using `publicProcedure` (no auth required for these endpoints). Import from Plan 01 auth modules.

**Procedures:**

1. `register` (mutation):
   - Input: `{ email: string, password: string, firstName?: string, lastName?: string, invitationToken?: string }`
   - Validate: email format (Zod email), password min 8 chars with at least 1 uppercase, 1 lowercase, 1 number
   - Rate limit: `checkRegistrationRateLimit(ip)` -- get IP from tRPC context (add `ip` field to Context interface if not present; extract from `req.headers['x-forwarded-for']` or `req.socket?.remoteAddress` in context creation)
   - Check email not already registered (query users table)
   - Hash password with `hashPassword()`
   - Insert into `users` table
   - Generate email verification token with `generateToken()`, store hash in `emailVerificationTokens` with 1-hour expiry
   - Send verification email via `sendVerificationEmail()`
   - If `invitationToken` provided: validate invitation (hash token, find in organizationInvitations where status='pending' and not expired), if valid accept it (create membership, update invitation status to 'accepted')
   - Return `{ userId: string, message: "Registration successful. Please check your email to verify your account." }`

2. `login` (mutation):
   - Input: `{ email: string, password: string, mfaToken?: string }`
   - Rate limit: `checkLoginRateLimit(email, ip)`
   - Find user by email
   - Verify password with `verifyPassword(storedHash, password, hashType)`
   - If `needsRehash` (bcrypt migration): rehash with Argon2id and update user record
   - If user has MFA enabled and no mfaToken provided: return `{ requiresMfa: true, userId: string }` (client shows MFA input)
   - If user has MFA enabled and mfaToken provided: verify with `verifyMfaToken()` or `verifyBackupCode()` (try backup if TOTP fails)
   - If email not verified: return error "Please verify your email before logging in"
   - Generate token family ID with nanoid
   - Sign access token with `signAccessToken({ userId, orgId, orgRole, hasMfa })`
   - Sign refresh token with `signRefreshToken({ userId, tokenFamily })`
   - Store refresh token hash in `refreshTokens` table with familyId and 7-day expiry
   - Update user `lastLoginAt`
   - For orgId/orgRole: query `organizationMemberships` for user's first org (or null if no orgs yet)
   - Return `{ accessToken, refreshToken, user: { id, email, firstName, lastName, mfaEnabled }, org: { id, name, role } | null }`

3. `refresh` (mutation):
   - Input: `{ refreshToken: string }`
   - Rate limit: verify and extract userId, then `checkRefreshRateLimit(userId)`
   - Verify refresh token JWT with `verifyRefreshToken()`
   - Hash the token, look up in `refreshTokens` table
   - If token already revoked/used: REVOKE entire token family (all tokens with same familyId), throw "Token reuse detected"
   - Mark current token as revoked, set `replacedByHash`
   - Generate new access + refresh token pair
   - Store new refresh token hash in DB
   - Re-query user's current org membership for fresh orgId/orgRole
   - Return `{ accessToken, refreshToken }`

4. `verifyEmail` (mutation):
   - Input: `{ token: string }`
   - Hash token with `hashToken()`
   - Find in `emailVerificationTokens` where hash matches and not expired and not used
   - Mark token as used, update user `emailVerified = true`
   - Return `{ success: true }`

5. `requestPasswordReset` (mutation):
   - Input: `{ email: string }`
   - Rate limit by IP
   - Find user by email. If not found, return success anyway (prevent email enumeration)
   - Generate token, store hash in `passwordResetTokens` with 1-hour expiry
   - Send password reset email
   - Return `{ message: "If an account exists with that email, a reset link has been sent." }`

6. `resetPassword` (mutation):
   - Input: `{ token: string, newPassword: string }`
   - Validate password strength (same rules as register)
   - Hash token, find in `passwordResetTokens` where not expired and not used
   - Hash new password with Argon2id
   - Update user password, mark token as used
   - Revoke ALL refresh tokens for this user (security: force re-login everywhere)
   - Return `{ success: true }`

7. `setupMfa` (mutation) -- requires auth (use authProcedure pattern by checking ctx.userId manually since authProcedure imports @clerk/backend currently):
   - For now, accept a userId from a custom header or implement a lightweight auth check by verifying the access token from Authorization header using `verifyAccessToken()` directly
   - Call `generateMfaSecret(user.email)`
   - Return `{ secret, qrCodeDataUrl, backupCodes }` (backup codes shown once)

8. `verifyMfaSetup` (mutation):
   - Input: `{ userId: string, token: string, secret: string, hashedBackupCodes: string[] }`
   - Verify the token against the secret to confirm user scanned QR correctly
   - Update user: `mfaEnabled = true`, `mfaSecret = secret`, `mfaBackupCodes = hashedBackupCodes`
   - Return `{ success: true }`

9. `switchOrganization` (mutation):
   - Input: `{ organizationId: string }` + requires valid access token
   - Verify user has membership in target org
   - Sign new access token with updated orgId/orgRole
   - Return `{ accessToken, org: { id, name, role } }`

**Important implementation notes:**
- Use the public schema `db` (from `apps/api/src/db/client.ts`) for auth queries, NOT tenant-scoped DB
- All token storage uses hashed values (never store plaintext tokens in DB)
- The router uses `publicProcedure` for unauthenticated endpoints (register, login, verifyEmail, requestPasswordReset, resetPassword)
- For authenticated endpoints (setupMfa, verifyMfaSetup, switchOrganization), manually verify access token from Authorization header since we can't use the existing protectedProcedure yet (it still uses Clerk)
