  <action>
Import new schemas: shareDocumentSchema, revokeDocumentPermissionSchema, shareFolderSchema, revokeFolderPermissionSchema
Import loadDocumentPermissions from auth/abilities

Add five new procedures to documentRouter:

**1. shareDocument** (mutation, protectedProcedure):
- Input: shareDocumentSchema
- Load abilities with loadProjectAbilities
- Verify document exists, get projectId and folderId
- Check user has "update" permission on Document (only owners/editors can share)
- Validate target userId exists in tenant (query user_profiles)
- Use INSERT ... ON CONFLICT (documentId, userId) DO UPDATE to upsert permission
- Set grantedBy = current userId, grantedAt = now()
- Create audit log: AuditAction.UPDATE, entityType: "Document", changes: { permissions: { granted: { userId, permissionLevel } } }
- Return success

**2. revokeDocumentPermission** (mutation, protectedProcedure):
- Input: revokeDocumentPermissionSchema
- Verify document exists and user has "update" permission
- Check permission record exists and was granted by current user OR user is admin/PM for project
- Delete from document_permissions where documentId and userId match
- Create audit log: AuditAction.UPDATE, entityType: "Document", changes: { permissions: { revoked: { userId } } }
- Return success

**3. shareFolder** (mutation, protectedProcedure):
- Input: shareFolderSchema
- Verify folder exists, get projectId
- Check user has "update" permission on Folder subject (add to abilities.ts if missing - follow Document pattern)
- Validate target userId exists in tenant
- Use INSERT ... ON CONFLICT (folderId, userId) DO UPDATE to upsert permission
- Set includeSubfolders from input (default true), grantedBy = current userId
- Create audit log: AuditAction.UPDATE, entityType: "Folder", changes: { permissions: { granted: { userId, permissionLevel, includeSubfolders } } }
- Return success

**4. revokeFolderPermission** (mutation, protectedProcedure):
- Input: revokeFolderPermissionSchema
- Verify folder exists and user has "update" permission
- Check permission record exists and was granted by current user OR user is admin/PM
- Delete from folder_permissions where folderId and userId match
- Create audit log: AuditAction.UPDATE, entityType: "Folder", changes: { permissions: { revoked: { userId } } }
- Return success

**5. getSharedWithMe** (query, protectedProcedure):
- Input: none (uses current userId from ctx)
- Call loadDocumentPermissions(db, schema, userId) to get explicit grants
- Query documents where id IN documentIds OR folderId IN folderIds
- Join to get project name, folder name, file metadata
- Include permissionLevel (view or edit) and grantedBy user info
- Order by permission grantedAt DESC (most recently shared first)
- Limit 100 results
- Return array of { document, project, folder, permissionLevel, grantedBy, grantedAt }

All procedures use existing patterns: loadProjectAbilities for permission checks, TRPCError for errors, createAuditLog for audit trail.

Update existing document.list and document.getDownloadUrl procedures to check loadDocumentPermissions in addition to project-level abilities. If user not on project team but has explicit permission, allow access.

- After ability check fails for project-level access, fall back to checking loadDocumentPermissions
- If documentId in documentIds OR document.folderId in folderIds, allow download
- If still no permission, throw FORBIDDEN

- Same pattern as getDownloadUrl - check project abilities first, fall back to explicit permissions

**document.delete:**
- Check project abilities for "delete" permission first
- Check explicit permissions: if documentId in documentEditIds, allow delete

Add helper function checkDocumentAccess(abilities, explicitPerms, document, action) that:
1. Tries abilities.throwUnlessCan(action, "Document")
2. On failure, checks if document.id or document.folderId in relevant explicit permission set
3. Throws FORBIDDEN if neither grants access

Use this helper consistently across all document access procedures.
