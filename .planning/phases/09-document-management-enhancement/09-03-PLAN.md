  <action>
Add two new tables to createTenantSchema function:

**document_permissions table:**
- id: UUID primary key
- documentId: UUID foreign key to documents (on delete cascade)
- userId: TEXT not null (Clerk user ID of person granted access)
- permissionLevel: TEXT not null (view, edit) - view allows read/download, edit allows update/version upload
- grantedBy: TEXT not null (Clerk user ID who shared)
- grantedAt: TIMESTAMP with timezone
- expiresAt: TIMESTAMP with timezone (nullable - null means no expiration)
- Unique constraint on (documentId, userId) - one permission level per user per document

**folder_permissions table:**
- id: UUID primary key
- folderId: UUID foreign key to folders (on delete cascade)
- userId: TEXT not null (Clerk user ID of person granted access)
- permissionLevel: TEXT not null (view, edit)
- includeSubfolders: BOOLEAN not null default true (cascade to child folders)
- grantedBy: TEXT not null
- grantedAt: TIMESTAMP with timezone
- expiresAt: TIMESTAMP with timezone (nullable)
- Unique constraint on (folderId, userId)

Add indexes for permission lookup:
- document_permissions: index on (documentId, userId) for fast permission checks
- folder_permissions: index on (folderId, userId)
- document_permissions: index on userId for "shared with me" queries

Insert tables into schema export in createTenantSchema return statement.

- revokeDocumentPermissionSchema: { documentId: UUID, userId: string }
- shareFolderSchema: { folderId: UUID, userId: string, permissionLevel: documentPermissionLevelEnum, includeSubfolders: boolean (default true), expiresAt: datetime (optional) }
- revokeFolderPermissionSchema: { folderId: UUID, userId: string }

**In apps/api/src/auth/abilities.ts:**

Create helper function loadDocumentPermissions(db, schema, userId) that queries:
1. document_permissions where userId and (expiresAt is null OR expiresAt > now())
2. folder_permissions where userId and (expiresAt is null OR expiresAt > now())

Returns: { documentIds: Set<string>, folderIds: Set<string>, documentEditIds: Set<string>, folderEditIds: Set<string> }

Update defineAbilitiesFor function to accept optional explicitDocumentPermissions parameter.

Enhance Document permission rules:
- Existing project-level permissions remain primary (admin/PM can manage all)
- Add secondary check: if document.id is in explicitDocumentPermissions.documentIds OR document.folderId is in explicitDocumentPermissions.folderIds, user can read
- Add secondary check: if document.id is in explicitDocumentPermissions.documentEditIds OR document.folderId is in explicitDocumentPermissions.folderEditIds, user can update

Use ForbiddenError.from(abilities).throwUnlessCan pattern. Document explicitly: "Explicit permissions supplement, not replace, project-level permissions."

Do NOT use this helper in defineAbilitiesFor by default - it will be called explicitly in document router for performance (avoid N+1 queries). Add comment explaining usage pattern.
