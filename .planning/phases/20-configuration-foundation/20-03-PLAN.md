  <action>
Create a migration script to add the missing columns to existing tenant schemas.

**File location:** apps/api/src/tenant/migrate-phase20-schema.ts

**Pattern to follow:** Phase 8 QBO migration pattern (see apps/api/src/migrate-phase8-qbo.ts) and Phase 13 migration (see apps/api/src/tenant/migrate-phase13-sidebar.ts referenced in STATE.md decisions).

**Script structure:**
1. Import dotenv, configure at top
2. Import pool from db/pool.ts
3. Query all active tenants from public.organizations (slug, tenant_schema)
4. For each tenant schema:
   - Check if allow_personal_templates column exists (avoid duplicate adds)
   - If missing: `ALTER TABLE company_profiles ADD COLUMN allow_personal_templates BOOLEAN DEFAULT true`
   - Check if sov_grouping_method column exists
   - If missing: `ALTER TABLE company_profiles ADD COLUMN sov_grouping_method TEXT DEFAULT 'csi'`
   - Log results (tenant name, columns added)
5. Close pool, exit with code 0 on success

**Column existence check SQL pattern:**
```sql
SELECT EXISTS (
  SELECT 1 FROM information_schema.columns
  WHERE table_schema = '${schemaName}'
  AND table_name = 'company_profiles'
  AND column_name = 'allow_personal_templates'
)
```

**Why these defaults:**
- allow_personal_templates DEFAULT true: Per Phase 17-03 decision, permissive default treats null as true, so existing companies can create personal templates unless explicitly disabled
- sov_grouping_method DEFAULT 'csi': Most common grouping method, matches comment in schema definition

After creating the script, run it:
