### Known Gap (By Design)

**Counter not incremented on `project.update`**
- When a user edits an existing project and changes its job number to a manually-entered value, `nextSequenceNumber` in `company_profiles` is not advanced.
- Impact: if counter is at 30 and user manually sets a project to "26-0050", the counter stays at 30. Future auto-gen will eventually produce "26-0050" when it reaches 50. Phase 22 duplicate detection catches this at assignment time and prevents the conflict — but requires the user to resolve it manually.
- Decision: Scoped to `project.create` only per Phase 21-01 plan. Accepted as design limitation.
- Mitigation: Duplicate check (Phase 22) catches the collision. Admin can manually advance "Next Job Number" in company settings via the new override field (Quick Task 24).

### Cosmetic Gap

**project-form preview doesn't account for year rollover**
- Preview uses raw `nextSequenceNumber`; actual generation uses `computeNextSequenceNumber` (rollover-aware).
- Impact: After year change, preview shows stale sequence; actual generated number resets to `startingSequenceNumber`. Cosmetic only — the correct number is always generated.
- Mitigation: Settings page preview is correct. project-form preview is pre-creation and rarely compared against expectations.
